## 1. 数据流水线智能判断

### 问题

`DatasetPipeline.run()` 每次执行都无差别走完整流程：格式转换 → 数据划分 → 落盘 → 写 YAML。即使 `data/processed/fire/` 和 `configs/datasets/fire.yaml` 已经存在，也会全部重建，浪费时间和计算资源。

### 原理

在 `run()` 入口处增加一个守护检查点。当用户指定 `--skip-if-exists` 时，先检查两个条件：

1. **YAML 配置文件是否存在** — `configs/datasets/<name>.yaml`
2. **处理后数据是否已落盘** — `data/processed/<name>/train/images/` 和 `val/images/` 目录下是否有文件

两个条件同时满足 → 认为数据集已划分完成，直接返回 `{"skipped": True}`，跳过全部后续逻辑。不满足则正常执行流水线。

```
run()
  │
  ├─ skip_if_exists=True ?
  │    ├─ YES → _already_split() ?
  │    │         ├─ YES → return {"skipped": True}   ← 跳过
  │    │         └─ NO  → 继续执行
  │    └─ NO  → 继续执行
  │
  ├─ _run_preserve_split()  or  _run_resplit()
  └─ ...
```

### 代码修改

**`orchestrator.py` — 新增 `skip_if_exists` 参数和 `_already_split()` 方法：**

```python
# __init__ 新增参数
def __init__(self, ..., skip_if_exists: bool = False):
    ...
    self.skip_if_exists = skip_if_exists

# run() 头部增加守护逻辑
def run(self) -> Dict:
    if self.skip_if_exists and self._already_split():
        logger.info("数据集 %r 已划分，跳过流水线...", self.dataset_name)
        return {"skipped": True, "yaml": str(self.yaml_out)}
    # ... 原有逻辑

# 核心检查方法
def _already_split(self) -> bool:
    if not self.yaml_out.exists():
        return False
    train_dir = self.output_dirs.train_images  # data/processed/<name>/train/images
    val_dir = self.output_dirs.val_images
    if not train_dir.is_dir() or not val_dir.is_dir():
        return False
    has_train_files = any(train_dir.iterdir())
    has_val_files = any(val_dir.iterdir())
    return has_train_files and has_val_files
```

**`transform_data.py` — CLI 暴露 `--skip-if-exists` flag：**

```python
p.add_argument("--skip-if-exists", action="store_true",
               help="如果数据集已划分完成，跳过流水线不重复执行")
```

### 使用方式

```bash
# 第一次运行：正常执行流水线
odp-transform --dataset fire --format pascal_voc

# 第二次运行：检测到已划分，直接跳过
odp-transform --dataset fire --format pascal_voc --skip-if-exists
# 输出: 数据集 'fire' 已划分，跳过流水线。YAML: ..., 处理后数据: ...
```

## 2. 项目重置备份功能

### 问题

`odp-reset` 原本使用 `shutil.rmtree()` 直接删除，不可逆。用户误操作或需要回滚时无法恢复。

### 原理

在删除步骤之前插入一个打包备份阶段。利用 Python 标准库 `zipfile`，将待删除目录中的所有文件以相对路径写入一个带时间戳的 `.zip` 文件，存入 `backups/` 目录。

流程变为：

```
确认删除
  │
  ├─ --no-backup ?
  │    ├─ YES → 跳过备份
  │    └─ NO  → _create_backup()
  │              ├─ 遍历 deletable 目录列表
  │              ├─ zipfile.ZipFile(backups/reset_backup_20260709_xxx.zip, 'w')
  │              ├─ 逐个文件写入，arcname 为相对 ROOT_DIR 的路径
  │              └─ 返回 backup_path
  │
  └─ _execute_delete() → 逐个 shutil.rmtree()
       └─ 打印备份路径
```

### 代码修改

**`paths.py` — 新增 `BACKUPS_DIR` 常量：**

```python
BACKUPS_DIR: Path = ROOT_DIR / "backups"
```

**`reset_project.py` — 新增 `_create_backup()` 函数：**

```python
def _create_backup(deletable: list[tuple[Path, int, int]]) -> Path | None:
    if not deletable:
        return None

    BACKUPS_DIR.mkdir(parents=True, exist_ok=True)
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    backup_path = BACKUPS_DIR / f"reset_backup_{timestamp}.zip"

    with zipfile.ZipFile(backup_path, "w", zipfile.ZIP_DEFLATED) as zf:
        for dir_path, _, _ in deletable:
            if not dir_path.exists():
                continue
            for f in dir_path.rglob("*"):
                if f.is_file():
                    # 以项目根目录为参考的相对路径
                    arcname = str(f.relative_to(ROOT_DIR))
                    zf.write(f, arcname)

    return backup_path
```

**`reset_project()` — 集成备份流程：**

```python
def reset_project(yes=False, force=False, dry_run=False, no_backup=False) -> int:
    ...
    # 在删除前执行备份
    backup_path = None
    if not no_backup:
        backup_path = _create_backup(deletable)
    else:
        logger.warning("已通过 --no-backup 跳过备份，直接删除。")

    _execute_delete(deletable, backup_path)
    ...
```

### 使用方式

```bash
odp-reset               # dry-run（安全，只打印不操作）
odp-reset --yes         # 备份 → 删除
odp-reset --yes --no-backup  # 跳过备份，直接删除
odp-reset --yes --force      # 跳过交互确认 + 备份 → 删除
```

备份文件位置：`backups/reset_backup_20260709_201234.zip`，内容结构保持原项目目录层次。

## 3. Word 格式质检报告

### 问题

数据质检原本只输出 JSON、CSV、HTML 三种格式。用户希望有 Word（`.docx`）格式以便在 Office 环境中编辑和归档。

### 原理

使用 `python-docx` 库操作 Open XML 格式，逐段构造文档：

1. **标题区**：文档标题 + 运行摘要（run_id、总体级别、耗时）
2. **检测概览表**：4 列（PASS / INFO / WARNING / ERROR 计数）
3. **数据集信息表**：YAML 路径、任务类型、类别数、类别列表等
4. **数据集摘要表**：每个 split 的图片数、有标注图片数、实例数
5. **检测项结果表**：检测项名称、级别、摘要
6. **问题详情表**（8 列）：级别、检测项、Split、文件、行号、问题类型、详情、**修复建议**
7. **原始产物列表**：JSON / CSV / HTML 文件引用

关键挑战是中文支持——通过设置 `run.font.name = "宋体"` 和 `rFonts.set(qn("w:eastAsia"), "宋体")` 确保 Word 中正确渲染中文字符。

### 代码修改

**`artifacts.py` — 新增 `write_docx_report()` 函数**（130 行，见文件末尾）：

## 4. 统一报告 API

### 问题

训练报告（`runs/detect/train*/report.md`）、评估报告（`runs/val*/report.md`）、质检报告（`runs/data_validation/*/report.html`）、对比报告（`runs/compare/*/`）、数据流水线配置（`configs/datasets/*.yaml`）散落在项目各处，没有一个统一入口查阅和管理所有报告。

### 原理

设计一个 `ReportHub` 类，内部通过 5 个专用扫描方法覆盖所有已知报告位置。每次 `scan()` 遍历文件系统，将发现的报告封装为统一的 `ReportInfo` 数据结构，再按类型、时间排序。

```
ReportHub
  │
  ├─ scan()
  │    ├─ _scan_training_reports()      # runs/detect/*/report.{md,html} + od_audit.json
  │    ├─ _scan_evaluation_reports()    # runs/val/*/report.{md,html} + od_audit.json
  │    ├─ _scan_validation_reports()    # runs/data_validation/*/report.{html,json,docx}
  │    ├─ _scan_comparison_reports()    # runs/compare/*/
  │    └─ _scan_data_pipeline_reports() # configs/datasets/*.yaml
  │
  ├─ list_reports(type)    # 按类型过滤
  ├─ get_report(run_id)    # 按 ID 精确查找
  ├─ summary()             # 各类型数量统计
  └─ export_all(dir, fmt)  # 统一导出 + 生成 index.html
```

### 核心数据结构

```python
class ReportType:
    TRAINING = "training"        # 模型训练
    EVALUATION = "evaluation"    # 模型评估
    VALIDATION = "validation"    # 数据质检
    COMPARISON = "comparison"    # 模型对比
    DATA_PIPELINE = "data_pipeline"  # 数据流水线

@dataclass
class ReportInfo:
    report_type: str           # 类型标识
    name: str                  # 人类可读名称
    run_id: str                # 运行标识
    run_dir: Path              # 运行目录
    created_at: str            # 创建时间
    markdown_path: Path | None # MD 报告路径
    html_path: Path | None     # HTML 报告路径
    docx_path: Path | None     # DOCX 报告路径
    json_path: Path | None     # JSON 数据路径
    metadata: dict             # 附加元数据（训练配置、指标等）
```

### 新增文件

**`report_api/__init__.py`** — 公共 API 导出

**`report_api/hub.py`** — `ReportHub` 完整实现（~390 行）

**`cli/reports.py`** — `odp-reports` CLI 命令，4 个子命令：
- `list` — 列出报告（支持 `--type` 过滤）
- `show <run_id>` — 查看单份报告详情
- `export` — 统一导出（`-o` 目录，`-f` 格式）
- `summary` — 各类型数量统计

### 使用方式

```bash

odp-reports show train-20260709-xxx       # 报告详情
```
