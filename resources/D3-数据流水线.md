## 1.1 一种格式,一个纯函数(直接就能跑)

需求很具体:把 VOC 格式的 XML 转成 YOLO 格式的 txt。先把两种格式说清楚——它们只差在"框怎么记":

- **VOC**:每张图一个 `.xml`,框记成左上、右下四个**绝对像素**坐标 `(xmin, ymin, xmax, ymax)`。
- **YOLO**(训练要用):每张图一个 `.txt`,每行 `cls_id cx cy w h`,坐标**全部归一化到 [0,1]**(即除以图宽 / 图高)。

所以"VOC→YOLO"本质就是:逐个读 xml、把像素坐标换算成归一化坐标、写 txt。最朴素的写法——**一个函数,直接调用**。

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert.py`** · 约 40 行
> **内容**:一个函数 `convert_voc_to_yolo(annotations_dir, out_labels_dir)`——读所有 `.xml`,换算成 YOLO 归一化坐标写 txt,返回"出现过的类名列表"。
> **为什么这样设计**:此刻**故意不引入任何架构**——只有一种格式,一个普通函数、用普通参数、直接调用就够。类名按"首次出现"累积、下标即 `class_id`,保证不同机器上编号一致。
> **现在为什么不做别的**:学员常问"要不要先写个基类 / 工厂?"——不要。只有一个实现时,任何分发结构都是**没东西可分发的空壳**;等第二种格式出现、调用方被迫 `if/elif`(1.2),抽象才有对象。**抽象是被第二个实现逼出来的,不是预设的。**

```python
"""data_pipeline/convert.py —— 第一版:就一个普通函数,把 VOC 转成 YOLO。

VOC 标注:每张图一个 .xml,框是绝对像素坐标 (xmin, ymin, xmax, ymax)。
YOLO 标注:每张图一个 .txt,每行 `cls_id cx cy w h`,坐标全部归一化到 [0,1]。
现在没有任何架构 —— 只有一种格式,一个函数,直接调用就够了。
"""
import xml.etree.ElementTree as ET
from pathlib import Path

def convert_voc_to_yolo(annotations_dir: Path, out_labels_dir: Path) -> list[str]:
    out_labels_dir.mkdir(parents=True, exist_ok=True)
    classes: list[str] = []                       # 类名按"首次出现"累积,下标即 class_id

    for xml_path in sorted(annotations_dir.glob("*.xml")):   # sorted:顺序确定,编号才稳定
        root = ET.parse(xml_path).getroot()
        size = root.find("size")
        W = float(size.findtext("width"))         # 这张图的宽,用来把 x 归一化
        H = float(size.findtext("height"))        # 这张图的高,用来把 y 归一化

        lines: list[str] = []
        for obj in root.findall("object"):        # 一张图可能有多个框
            name = obj.findtext("name")
            if name not in classes:
                classes.append(name)              # 第一次见到这个类,登记进列表
            cls_id = classes.index(name)          # 类名 → 数字编号(列表下标)

            b = obj.find("bndbox")
            xmin = float(b.findtext("xmin")); ymin = float(b.findtext("ymin"))
            xmax = float(b.findtext("xmax")); ymax = float(b.findtext("ymax"))
            cx = (xmin + xmax) / 2 / W             # 像素坐标 → 归一化中心点 + 宽高
            cy = (ymin + ymax) / 2 / H
            bw = (xmax - xmin) / W
            bh = (ymax - ymin) / H
            lines.append(f"{cls_id} {cx:.6f} {cy:.6f} {bw:.6f} {bh:.6f}")

        out = out_labels_dir / (xml_path.stem + ".txt")
        out.write_text("\n".join(lines), encoding="utf-8")   # 没框也写空 txt,保证图-标注配对

    return classes                                # 顺便返回"这批数据有哪些类"
```

> 📌 三件**学员一定会问**的小事,都已写进注释,老师可以主动点一句:
> - `sorted(...)`:让文件处理顺序确定,这样 `class_id` 在不同机器/不同次运行上一致(否则今天 `head=0`、明天 `head=1`,训练标签全乱)。
> - 类名"首次出现即登记":所以 `class_id` 的顺序由扫描顺序决定,不是凭空指定的。
> - **没有框也写一个空 `.txt`**:下游靠"每张图都有一个同名标注文件"来配对;缺了它,纯背景图会被当成"没标注"而漏掉。

**这里没有 `import registry`、没有 `@register`——那些东西现在根本不存在,也用不上。**

```python
from pathlib import Path
import random

ROOT = Path(__file__).parent / "data" / "raw" / "demo"

def xml_for(stem, w, h, objects):
    objs = ""
```

## 1.2 加第二种格式 COCO:`if/elif` 自然冒出来

老板第二天加需求:"也要支持 COCO。" COCO 的标注是整个数据集**一个** `instances.json`,框记成 `[x, y, w, h]`(左上角 + 宽高,绝对像素)。**读法和 VOC 完全不同,但读完之后归一化、写 txt 的逻辑一模一样。** 我们照样写一个 `convert_coco_to_yolo(...)`,再加一个**按字符串选函数**的 `run()`——都**追加到 `convert.py`**:

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert.py`(追加部分)** · 约 40 行
> **内容**:`convert_coco_to_yolo(annotations_dir, out_labels_dir)`(读那个 json,换算写 txt)、`run(fmt, ...)`(按字符串 `fmt` 用 `if/elif` 决定调哪个转换器)。
> **为什么这样设计**:两个转换器签名一致 `(annotations_dir, out_labels_dir) -> list[str]`,所以 `run()` 能用同样的方式调它们;`run()` 就是那个"按名字选函数"的中心。
> **现在为什么不做别的**:`run()` 里这段 `if/elif` 看着无害——本节的全部意义,就是让你**亲眼看到它马上会出问题**,从而理解为什么需要后面那一套。**先撞,再修。**

```python
# ── 阶段 1.2 追加到 convert.py 顶部的 import ──────────────
import json
from collections import defaultdict

def convert_coco_to_yolo(annotations_dir: Path, out_labels_dir: Path) -> list[str]:
    """COCO -> YOLO。整个数据集一个 .json,框是 [x,y,w,h](左上角+宽高,绝对像素)。"""
    out_labels_dir.mkdir(parents=True, exist_ok=True)
    json_path = sorted(annotations_dir.glob("*.json"))[0]    # COCO 习惯单个 json
    data = json.loads(json_path.read_text(encoding="utf-8"))

    cat_name = {c["id"]: c["name"] for c in data["categories"]}   # 类别 id → 名字
    img_info = {im["id"]: im for im in data["images"]}            # 图 id → 图信息
    per_image: dict[int, list] = defaultdict(list)               # 图 id → 它的所有标注
    for ann in data["annotations"]:
        per_image[ann["image_id"]].append(ann)

    classes: list[str] = []
    for img_id, im in img_info.items():
        W, H = float(im["width"]), float(im["height"])
        stem = im["file_name"].rsplit(".", 1)[0]   # 去扩展名,作为 txt 文件名
        lines: list[str] = []
        for ann in per_image.get(img_id, []):
            name = cat_name[ann["category_id"]]
            if name not in classes:
                classes.append(name)
            cls_id = classes.index(name)
            x, y, w, h = ann["bbox"]                # COCO:左上角 (x,y) + 宽高 (w,h)
            cx = (x + w / 2) / W
            cy = (y + h / 2) / H
            lines.append(f"{cls_id} {cx:.6f} {cy:.6f} {w / W:.6f} {h / H:.6f}")
        (out_labels_dir / (stem + ".txt")).write_text("\n".join(lines), encoding="utf-8")
    return classes

def run(fmt: str, annotations_dir: Path, out_labels_dir: Path) -> list[str]:
    """根据 fmt 字符串,决定调哪个转换器。最直接的办法:if/elif。"""
    if fmt == "pascal_voc":
        return convert_voc_to_yolo(annotations_dir, out_labels_dir)
    elif fmt == "coco":
        return convert_coco_to_yolo(annotations_dir, out_labels_dir)
    else:
        raise ValueError(f"不支持的格式: {fmt}")
```

## 1.3 🧱 撞墙①:同一段判断,悄悄散进了好几个文件

`run()` 里那段 `if/elif` 看着还行。但问一句:**做"按格式选函数"这件事的地方,真的只有这一处吗?**

同一个"我支持哪些格式"的事实,被**抄进了好几个文件**:

```
cli.py            pipeline.py        test_fixture.py
if voc:  …        if voc:  …         if voc:  …
elif coco: …      elif coco: …       elif coco: …
elif 新: ←要加     elif 新: ←也要加     忘了加 ← 静默出 bug
```

设想你某天加了个 `labelme` 格式,改了 `cli.py` 和 `pipeline.py`,却忘了改 `test_fixture.py`——测试照样用旧逻辑跑、还全绿,你以为没事,结果某条路径根本不认 `labelme`,直到上线被用户踩中才发现。**改一处、漏一处,那条没改到的路径就悄悄"不支持"了,还不报错。** 这种毛病有个俗称叫**漂移(drift)**。

> 💡 **金句**:**"`if/elif` 的本质问题不是'丑',是'分支信息会跨文件复制'。同一份真相散在 N 个文件里,改一处忘一处,迟早打架。"**

看到这儿,第一反应很自然:把这堆重复的判断收到一个地方去。**这正是阶段 2 的起点。**

```bash
git add make_demo.py make_coco_demo.py apps/platform/src/od_platform/data_pipeline/convert.py
git commit -m "feat(data_pipeline): naive VOC/COCO converters + if/elif dispatch (hits wall #1)"
```

# 阶段 2:撞墙后重构 —— 注册表与自动注册

> 这一节不背定义,看着注册表**怎么从那段 `if/elif` 一步步长出来**:先收成中间层(治了漂移、还别扭)→ 换成一张表 → 让实现自己报到 → 撞上空表 → 开门自动叫醒。等问题攒够,注册表会自己浮现——到那时,它的每一行你都知道为什么。

## 2.1 第一次抢救:中间层(治了漂移,却还是别扭)

最直接的修法:写一个**中间函数**,把所有 `if/elif` 收进去;其它文件(`cli` / `pipeline` / 测试)都不再各自判断,统一来调它。我们 1.2 写的那个 `run()`,其实就是这个中间层的雏形。

漂移**确实治好了**——全项目只剩这一处 `if/elif`,加格式只改这一个地方,几个调用方不会再各自漏改。这是实打实的进步。

可你心里还是有点别扭。哪里别扭?**每加一种格式,你还是得回来,在这段旧代码里再补一支 `elif`。** 你只是把"改好几处"压成了"改一处"——但"加东西,就得回去动已经写好的代码"这件事本身,一点没变;而且这个函数会随格式数一直变长。

```python
# 中间层 run():漂移没了,但它自己随格式数越长越长,且每加一种都得回来改它
def run(fmt, ...):
    if fmt == "pascal_voc": ...
    elif fmt == "coco": ...
    elif fmt == "yolo": ...        # ← 每加一种
    elif fmt == "labelme": ...     # ← 这里就再长一行,还得回来动这个旧文件
    else: raise ValueError(...)
```

> 🧭 **把这个别扭说成一句话**:有没有可能,让"加一种格式"**根本不用碰任何已经写好的代码**?——加的时候只**新增**东西(比如新建一个文件),旧代码一行都不动。这个朴素愿望有个正经名字叫**开闭原则**("对扩展开放,对修改封闭"),但名字先放着,**记住这个愿望就行**。

带着这个愿望,我们换个方向想。

## 2.2 换个方向:让每种格式"自己报到"

中间层为什么非写 `if/elif` 不可?因为是**它**在操心"哪个名字对应哪个函数"——所有对应关系都压在它一个人身上,每多一种它就得多记一条。这件事能不能反过来?

打个生活里的比方,一场活动要"按名字找到人":

- **办法 A(像中间层)**:主持人自己拿个小本子,把每个人的名字和座位都记下来。来一个新人,他就得翻开本子添一行。人越多,本子越厚,全压在他一个人身上。
- **办法 B(注册表)**:门口摆一本**签到册**,每个人进来**自己**签上"我叫某某,坐第几排"。主持人要找谁,翻签到册查一下就行——他什么都不用记,来多少新人都不关他的事。

**注册表就是办法 B**:让每个 converter 自己声明"我能处理 `coco`",中间那一层不再判断、只查一张表。这张"名字 → 函数"的表,就是**注册表(Registry)**。下面我们一步步把它搭出来——而且搭的过程本身,也是一步步撞出来的。

## 2.3 第一步:先用一张表,把 `if/elif` 换掉

"按名字找函数",本质就是查字典(Python 的 `dict` 就是"键 → 值"的表)。那我们就别写 `if/elif` 了,真用一个字典存"名字 → 函数":

```python
_REGISTRY = {}                                   # 名字 → 函数 的表
_REGISTRY["pascal_voc"] = convert_voc_to_yolo    # 注意:右边没有括号!
_REGISTRY["coco"] = convert_coco_to_yolo
# 用的时候再查表 + 加括号调用:
#     _REGISTRY[fmt](annotations_dir, out_labels_dir)
```

> 💡 **关键:函数本身也能当"值"存进字典。** `_REGISTRY["coco"] = convert_coco_to_yolo` 右边**没有括号**——存进去的是"这个函数"本身,不是"调用它的结果"。要用时再 `_REGISTRY[fmt](...)` 加括号调用。**把函数当普通值传来传去,是后面一切的基础。**

调用方的 `if/elif` 没了,这是进步。但你再看一眼——往字典里塞这几行,**还是集中写在一个地方**;加一种格式,还是得回这里加一行。我们真正想要的,是让每种格式**在自己的文件里**把自己写进表(对应签到册:让每个人自己签,而不是主持人替大家签)。

顺带说一件马上要做的事:要让一张表**一视同仁**地调所有 converter,它们的**签名必须统一**。阶段 1 的转换器是 `(annotations_dir, out_labels_dir)`,以后还要加白名单、任务类型等参数。与其每加一个参数就改所有 converter 的签名,不如把这些参数打成**一个参数包** `ConvertOptions` 传进去——以后加字段不破坏任何已有签名。

## 2.4 第二步:`@register` 让实现自己登记

怎么让 `coco.py` **自己**把自己写进表?用一个小装饰器 `@register`。先别被"装饰器"三个字唬住——它在这里做的事,说穿了就一句话:**把这个函数,按这个名字,写进表。**

最该说清的一点:`@register("coco")` 和你手写 `_REGISTRY["coco"] = convert_coco` **完全是一回事**,只是把"登记"这行挪到函数头顶,顺手而已:

```python
# 你写的(顺手版)              # 完全等价于(摊开版)
@register("coco")              def convert_coco(...):
def convert_coco(...):             ...
    ...                        _REGISTRY["coco"] = convert_coco
```

> 💡 **装饰器不是魔法**,就是"把登记这行写到函数头顶"的语法糖。而且这行登记,是在**"import 到 `coco.py`"的那一刻**才执行的——**记住这句,下一步要用。**

> 📌 **顺带一提"能力声明"**:我们这版的表里,每一条记录除了"函数",还会多存一句"我支持哪些 task(detect / segment)"。这样调度层在分发**之前**就能判断"这个格式不支持你要的 task",当场报清楚,而不是进到函数里才炸一个难懂的异常。这一层是注册表比裸 `if/elif` 多出来的价值,后面 `service` 会用到。

于是每个格式,在自己的文件里 `@register` 一下,就登记好了。看起来大功告成:加新格式 = 新建一个文件、写个 `@register("新名字")`,框架一行不用改。可你运行一下试试……

## 2.5 🧱 一个意外:表居然是空的

你写好了 `coco.py`、`pascal_voc.py`,信心满满地**只 import 那张表所在的文件**,查一下:

```python
# ckpt2b_empty.py —— 复现"空表"撞墙
from od_platform.data_pipeline.convert import registry as R
print("只 import registry 后,_REGISTRY =", dict(R._REGISTRY))     # 期望:空
import od_platform.data_pipeline.convert.converters.coco           # 手动 import 一个实现
print("import coco.py 后,_REGISTRY 的键 =", sorted(R._REGISTRY))   # 期望:出现 'coco'
```

实际运行(已验证):

```text
只 import registry 后,_REGISTRY = {}
import coco.py 后,_REGISTRY 的键 = ['coco']
```

**表是空的!** 为什么?回到上一步那句话——登记是在"import 到那个文件"的一刻才执行的。而关键事实是:

> ⚠️ **Python 不会执行你没 import 的文件。** 你只 import 了 `registry`(那张空表所在的文件),从没 import 过 `coco.py`,它顶上那行 `@register` 就**从没运行过**,自然没人往表里写。**代码写在那儿 ≠ 它被执行了**——没被 import,它就只是躺在硬盘上的文字。

上面第二行 `import ...coco` 之后键里立刻冒出 `'coco'`,正是这条规律的现场证据:**import 一个实现文件,就触发它顶上的 `@register`。** 问题一下清楚了:得有人在"用表"之前,把这些实现文件都 import 一遍。那……谁来做?

## 2.6 收尾:开门时,自动把它们都"叫醒"

最笨的办法:手写 `import coco, pascal_voc` 把它们一个个 import 进来。能用,但你发现没——那样"加一个文件,还得回来补一行 import",又绕回了 2.1 那个"加东西要改旧代码"的老毛病。**我们不想退回去。**

更好的办法:让程序自己来。**开门(第一次要用表)时,把存放实现的那个文件夹挨个扫一遍、逐个 import。** 这件事就是"自动发现"。下面把整张 `registry.py` 给全——它把前面几步(表 + `@register` + 自动发现)合到了一个文件:

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert/registry.py`** · 约 60 行
> **内容**:参数包 `ConvertOptions`、注册表条目 `ConverterEntry`(函数 + 能力声明)、装饰器 `register(...)`、查询 `get_converter` / `available_formats`,以及自动发现 `_lazy_init`(首次用表时扫 `converters/`)。
> **为什么这样设计**:① 参数包让所有 converter 签名统一成 `(input_dir, out_labels_dir, options)`;② `register` 是带参装饰器,登记后把函数**原样返回**;③ 自动发现用 `pkgutil` 扫目录,**加文件就被收录,连 import 列表都不用手写**——这一句是"加格式 = 加文件、框架一行不改"能**字面成立**的关键。
> **现在为什么不做别的**:为什么不在 `service.py` 启动时手写 `import` 列表?那就退回 2.1 的老毛病了(加文件还得改旧代码)。为什么扫描逻辑此刻写在这儿、不抽成公共件?因为**只有一个用例**——等阶段 4 的 split 第二张表也要同样的扫描,我们才抽进 `common/registry_utils.py`(第二次才抽象)。

```python
"""convert 框架层:一张表(格式名→条目) + 登记装饰器 @register + 参数包 ConvertOptions。

框架(本文件 + service.py)永远不动;加新格式 = 在 converters/ 加一个文件。
注:本阶段把"扫描 converters/ 目录"的逻辑【内联】在 _lazy_init 里;等阶段 4 的 split
   第二张表也要同样的扫描时,我们才把它抽进 common/registry_utils.py(第二次才抽象)。
"""
from __future__ import annotations

import logging
from dataclasses import dataclass, field
from pathlib import Path
from typing import Callable, Dict, List, Optional, Tuple

logger = logging.getLogger(__name__)

# ── 参数包:所有 converter 签名统一成 (input_dir, out_labels_dir, options) ──
@dataclass
class ConvertOptions:
    """所有格式转换共用的参数包。

    task   : 目标任务(detect / segment)。默认 detect 覆盖多数场景。
    classes: 类别白名单。
             None  = 用户没指定,由 converter 自行探测(仅 voc/coco 支持探测)。
             [...] = 用户指定的类别(同时决定 class_id 顺序)。
             ⚠️ 不要用 [] 当默认:None="没提供",[]="确实没有任何类别",语义不同。
    """
    task: str = "detect"
    classes: Optional[List[str]] = field(default=None)

# 一个 converter = 吃 (input_dir, out_labels_dir, options)、返回类名列表(顺序即 class_id)的函数。
ConverterFunc = Callable[[Path, Path, ConvertOptions], List[str]]

@dataclass(frozen=True)
class ConverterEntry:
    """注册表里一条记录:实现函数 + 它"能干哪些 task"的能力声明。"""
    func: ConverterFunc
    supported_tasks: Tuple[str, ...]

    def supports(self, task: str) -> bool:
        return task in self.supported_tasks

# 注册表本体:就是一个 {格式名: 条目} 的字典(模块级单例)
_REGISTRY: Dict[str, ConverterEntry] = {}

def register(format_name: str, *, supported_tasks: Tuple[str, ...]):
    """装饰器:把被装饰的函数(连同它支持的 task)登记进 _REGISTRY。

        @register("coco", supported_tasks=("detect", "segment"))
        def convert_coco(...): ...

    完全等价于在文件底部手写:
        _REGISTRY["coco"] = ConverterEntry(convert_coco, ("detect", "segment"))
    它在【该文件被 import 的那一刻】执行。
    """
    def decorator(func: ConverterFunc) -> ConverterFunc:
        if format_name in _REGISTRY:
            logger.warning("格式 %s 被重复注册,后者覆盖前者", format_name)
        _REGISTRY[format_name] = ConverterEntry(func=func, supported_tasks=tuple(supported_tasks))
        return func                       # 函数原样还回去,本身不变
    return decorator

def get_converter(format_name: str) -> ConverterEntry:
    """按 format 名取出条目。Raises: ValueError 未注册的格式。"""
    _lazy_init()
    if format_name not in _REGISTRY:
        raise ValueError(f"未注册的格式: {format_name!r}。已注册: {sorted(_REGISTRY)}")
    return _REGISTRY[format_name]

def available_formats() -> List[str]:
    """当前已注册的格式名(会先触发自动发现)。"""
    _lazy_init()
    return sorted(_REGISTRY)

# ── 自动发现:首次用表时,扫描 converters/ 把每个实现 import 一遍,触发它们的 @register ──
_LAZY_INITIALIZED = False

def _lazy_init() -> None:
    """扫描 converters/*.py 自动触发 @register。
    · 跳过 _ 开头的私有模块。
    · 标志位放在 import 全部成功【之后】——任何 import 失败都不污染状态,下次可重试。
    """
    global _LAZY_INITIALIZED
    if _LAZY_INITIALIZED:
        return
    import importlib, pkgutil
    from od_platform.data_pipeline.convert import converters
    for m in pkgutil.iter_modules(converters.__path__):
        if not m.name.startswith("_"):
            importlib.import_module(f"{converters.__name__}.{m.name}")
    _LAZY_INITIALIZED = True
```

再写薄薄的调度层。调用方只跟它说话,永远不写 `if/elif`:

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert/service.py`** · 约 16 行
> **内容**:`convert_data_to_yolo(input_dir, output_labels_dir, annotation_format, options)`——查表 + 校验 task + 分发。
> **为什么这样设计**:把"按名字分发"收口到一个入口;它**永不增长**——加多少格式都不改。
> **现在为什么不做别的**:为什么这里要 `entry.supports(task)` 校验?因为这是 `ConverterEntry` 那句"能力声明"的兑现点——格式不支持该 task,在这儿当场报清楚,而不是进到 converter 里炸难懂的异常。

```python
"""convert 调度层 —— 几行代码接住所有格式。

它是项目其它部分(指挥家 / CLI / 测试)唯一该调用的"转换入口"。
关键性质:【永不增长】—— 无论将来支持多少种格式,本文件一行都不用改,因为它只查表分发。
"""
from __future__ import annotations

from pathlib import Path
from typing import List

from od_platform.data_pipeline.convert.registry import ConvertOptions, get_converter

def convert_data_to_yolo(
    input_dir: Path,
    output_labels_dir: Path,
    annotation_format: str,
    options: ConvertOptions,
) -> List[str]:
    """统一入口:按 annotation_format 分发到具体 converter,返回类名列表。

    Raises:
        ValueError: 格式未注册,或该 converter 不支持请求的 task(在此提前 fail-fast)。
    """
    entry = get_converter(annotation_format)
    # 能力声明的兑现点:格式不支持该 task,在这里当场报清楚,而不是进到 converter 里炸。
    if not entry.supports(options.task):
        raise ValueError(
            f"格式 {annotation_format!r} 不支持 task={options.task!r}。支持: {entry.supported_tasks}"
        )
    return entry.func(input_dir, output_labels_dir, options)
```

现在把阶段 1 那个扁平的 `convert.py` **删掉**,把两个转换器**搬进 `converters/` 各自的文件**,逻辑一字不改,只是:改名、签名收成 `(input_dir, out_labels_dir, options)`、头顶加 `@register`、顺带支持白名单。物理目录直接长成"框架 / 实现"分离的样子:

```
data_pipeline/convert.py   ← 删掉
data_pipeline/convert/
├── registry.py      框架:表 + @register + 自动发现(永不增长)
├── service.py       框架:几行调度层(永不增长)
└── converters/      实现:想加新格式就加文件
    ├── pascal_voc.py
    └── coco.py
```

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert/converters/pascal_voc.py`** · 约 30 行
> **内容**:`@register("pascal_voc", supported_tasks=("detect",))` + `convert_voc(input_dir, out_labels_dir, options)`——和阶段 1 同样的 VOC→YOLO 逻辑,加白名单。
> **现在为什么不做别的**:为什么白名单(删类)能走 VOC?因为 VOC 的 xml 里**有类名**,能按名字筛掉不要的类——这一点 YOLO 做不到(阶段 3 会专门讲这个差异)。

```python
"""Pascal VOC -> YOLO 转换器(detect)。

VOC:每张图一个 .xml,框是绝对像素坐标 (xmin,ymin,xmax,ymax)。
YOLO:每张图一个 .txt,每行 `cls_id cx cy w h`,坐标全部归一化到 [0,1]。
本转换器的核心就是"逐个读框 → 像素换算成归一化 → 写 txt",顺带收集类名表。

它如何接入框架:头顶一行 @register 即把自己签进格式注册表,框架代码无需任何改动。
"""
from __future__ import annotations

import logging
import xml.etree.ElementTree as ET
from pathlib import Path
from typing import List

from od_platform.common.constants import AnnotationFormat, Task
from od_platform.data_pipeline.convert.registry import ConvertOptions, register

logger = logging.getLogger(__name__)

@register(AnnotationFormat.PASCAL_VOC, supported_tasks=(Task.DETECT,))
def convert_voc(input_dir: Path, out_labels_dir: Path, options: ConvertOptions) -> List[str]:
    out_labels_dir.mkdir(parents=True, exist_ok=True)

    # classes 既是"输出的类名表",也是"白名单":
    #   options.classes 为 None → discovering=True,边读边把新类名追加进去(探测模式);
    #   options.classes 给了名单 → discovering=False,不在名单的框直接跳过(=删类)。
    classes: List[str] = list(options.classes) if options.classes else []
    discovering = options.classes is None

    for xml_path in sorted(input_dir.glob("*.xml")):   # sorted:处理顺序确定 → class_id 跨机一致
        root = ET.parse(xml_path).getroot()
        size = root.find("size")
        W = float(size.findtext("width"))               # 用图宽把 x 归一化
        H = float(size.findtext("height"))              # 用图高把 y 归一化

        lines: List[str] = []
        for obj in root.findall("object"):              # 一张图可能有多个框
            name = obj.findtext("name")
            if name not in classes:
                if discovering:
                    classes.append(name)                # 探测模式:首次见到就登记
                else:
                    continue                            # 白名单模式:名单外的框跳过(删类)
            cls_id = classes.index(name)                # 类名 → 数字编号(列表下标)

            b = obj.find("bndbox")
            xmin = float(b.findtext("xmin")); ymin = float(b.findtext("ymin"))
            xmax = float(b.findtext("xmax")); ymax = float(b.findtext("ymax"))
            # 像素的左上/右下 → YOLO 的归一化中心点 + 宽高
            cx = (xmin + xmax) / 2 / W
            cy = (ymin + ymax) / 2 / H
            lines.append(f"{cls_id} {cx:.6f} {cy:.6f} {(xmax-xmin)/W:.6f} {(ymax-ymin)/H:.6f}")

        # 没框也写一个空 .txt:下游靠"每张图都有同名标注文件"配对,缺了它纯背景图会被漏掉。
        (out_labels_dir / (xml_path.stem + ".txt")).write_text("\n".join(lines), encoding="utf-8")

    return classes
```

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert/converters/coco.py`** · 约 30 行 —— `@register("coco", supported_tasks=("detect","segment"))` + `convert_coco(...)`,读法沿用阶段 1,加白名单。与 `pascal_voc.py` 签名完全一致,所以两者对调度层"长得一样"。

```python
"""COCO -> YOLO 转换器(detect / segment)。

COCO 与 VOC 的差异只在"读法":整个数据集一个 .json,框是 [x,y,w,h](左上角 + 宽高)。
读完之后,归一化、写 txt、白名单处理与 VOC 完全一样 —— 这也是为什么三种 converter 能
被同一张表一视同仁地调用:它们的输入/输出契约相同。
"""
from __future__ import annotations

import json
import logging
from collections import defaultdict
from pathlib import Path
from typing import List

from od_platform.common.constants import AnnotationFormat, Task
from od_platform.data_pipeline.convert.registry import ConvertOptions, register

logger = logging.getLogger(__name__)

@register(AnnotationFormat.COCO, supported_tasks=(Task.DETECT, Task.SEGMENT))
def convert_coco(input_dir: Path, out_labels_dir: Path, options: ConvertOptions) -> List[str]:
    out_labels_dir.mkdir(parents=True, exist_ok=True)

    # COCO 习惯整个数据集一个 json(取目录下第一个);先把它解析成几张查找表。
    data = json.loads(sorted(input_dir.glob("*.json"))[0].read_text(encoding="utf-8"))
    cat_name = {c["id"]: c["name"] for c in data["categories"]}   # 类别 id → 名字
    img_info = {im["id"]: im for im in data["images"]}            # 图 id → 图信息(含宽高/文件名)
    per_image = defaultdict(list)                                 # 图 id → 它的所有标注
    for ann in data["annotations"]:
        per_image[ann["image_id"]].append(ann)

    classes: List[str] = list(options.classes) if options.classes else []
    discovering = options.classes is None                         # 同 VOC:None=探测,[...]=白名单
    for img_id, im in img_info.items():
        W, H = float(im["width"]), float(im["height"])
        stem = im["file_name"].rsplit(".", 1)[0]                  # 去扩展名,作为输出 txt 的文件名
        lines: List[str] = []
        for ann in per_image.get(img_id, []):
            name = cat_name[ann["category_id"]]
            if name not in classes:
                if discovering:
                    classes.append(name)
                else:
                    continue
            cls_id = classes.index(name)
            x, y, w, h = ann["bbox"]                              # COCO:左上角 (x,y) + 宽高 (w,h)
            lines.append(f"{cls_id} {(x+w/2)/W:.6f} {(y+h/2)/H:.6f} {w/W:.6f} {h/H:.6f}")
        (out_labels_dir / (stem + ".txt")).write_text("\n".join(lines), encoding="utf-8")

    return classes
```

写 `@register(AnnotationFormat.PASCAL_VOC, ...)` 时,`"pascal_voc"` / `"detect"` 这些字符串,马上要在两个 converter、CLI、测试里反复出现——又是 1.3 那个漂移的味道。所以**现在**(不是开篇,是被这个具体需求逼到的此刻)给项目建一张"共同词汇表" `constants.py`,收下第一批词:

> 📄 **`apps/platform/src/od_platform/common/constants.py`(今天它的第一段)** · 约 20 行 —— 只有"标注格式名"和"任务类型"两段。划分策略、各种阈值,等后面撞到再加。**你会看着它一行行长出来。**

```python
"""项目级共享常量——所有模块的"共同词汇表"。
放这里的标准:多模块共享(>=2 处用到) + 纯定义无逻辑 + 极少改动。本文件按需增长。
"""
from __future__ import annotations
from typing import Tuple

# —— 标注格式名(阶段 2:@register 要用,且会在多个 converter/CLI/测试复用)——
class AnnotationFormat:
    PASCAL_VOC = "pascal_voc"
    COCO       = "coco"
    @classmethod
    def all(cls) -> Tuple[str, ...]:
        return (cls.PASCAL_VOC, cls.COCO)

# —— 任务类型(同上)——
class Task:
    DETECT  = "detect"
    SEGMENT = "segment"
    @classmethod
    def all(cls) -> Tuple[str, ...]:
        return (cls.DETECT, cls.SEGMENT)
```

## 回头看:加一种格式,从"改旧代码"变成"加一个文件"

把镜头拉回 1.3 那个问题:**加一种新格式,要动多少地方?** 一路走下来,这件事被彻底改写了:

| 同一件事 | 一开始(`if/elif`) | 走到注册表 |
|---|---|---|
| 加一种新格式 | 改旧代码:回去加 `elif`(可能好几处) | 只**新增一个文件** |
| "支持哪些格式"在哪 | 散在 N 段判断里 | 就一份:那张表 |
| 牵动几个文件 | 可能好几个 | 一个(新文件) |
| 分发代码会膨胀吗 | 会,越加越长 | 不会,永远那几行 |
| 谁决定"名字→函数" | 中心的 `if/elif` | 每个实现**自己声明** |

> 💡 **金句**:**"注册表把'谁支持什么'的决定权,从中心的 `if/elif` 下放给了每个实现自己(这个转向有个名字叫控制反转)。于是'扩展'从'改一段越来越长、还到处复制的代码',变成了'加一个互不打扰的小文件'。"** ——这就是 2.1 那个"加东西不碰旧代码"的愿望,终于兑现。

## ⚠️ 慢着:注册表什么时候是多余的

讲到这儿你可能想到处都用注册表。**先按住。** 它不是"更高级所以默认更好"的东西:

> **只有一种实现时,注册表纯属过度设计。** 没东西可分发,你却凭空多了表、装饰器、自动发现一堆零件,读代码的人还得绕一圈才看懂"到底调了啥"。它该上场的时刻是:你已经有 **2 个以上真实实现,而且预期还会继续加**(本课的格式 VOC/COCO/YOLO 三种、划分策略三种,D4 的检查项十几个,都满足)。**口诀:先朴素写,撞到 `if/elif` 到处复制、且确定还要继续加,才升级。**

回想我们这一路:正是撞到了第二种格式、撞到漂移、撞到中间层的别扭,被一个个问题推着,才走到注册表的。**这才是它该出现的方式——不是开局就架好,而是被需求逼出来。**

# 阶段 3:第三种格式 YOLO —— 当场验收"开闭",撞出"接口等价 ≠ 行为相同"

第三种来源很常见:数据本身**已经是 YOLO 格式**了——别人导出的、上一批训练剩下的。它不需要"换算",只需要把散落的 `.txt` **收拢**到我们的目录里。按阶段 2 立下的规矩,加它应该**只是往 `converters/` 丢一个文件**。我们来验证这句话是不是真的。

> 📄 **`apps/platform/src/od_platform/data_pipeline/convert/converters/yolo.py`** · 约 30 行
> **内容**:`@register("yolo", supported_tasks=("detect","segment"))` + `convert_yolo(input_dir, out_labels_dir, options)`——把原始 `.txt` 搬到目标目录(优先硬链接、跨盘退回复制)。
> **为什么这样设计**:YOLO→YOLO 是"直通",不解析、不换算,只搬运;硬链接零拷贝、省磁盘。
> **现在为什么不做别的**:① 为什么这里 `options.classes` 是**必填**、不像 voc/coco 可探测?因为 YOLO 的 txt 里**只有数字 `class_id`、没有类名**——名字只能由用户给(否则 yaml 的 `names` 没法写)。② 为什么不顺手支持 `--classes` 删类?见下方的边界说明:对 yolo 删类会让 yaml 和 txt 的 id 对不上,是个隐蔽的坑,所以这里**明确拒绝**。

```python
"""YOLO -> YOLO 直通转换器(detect / segment)。

"直通"的意思:源数据已经是 YOLO 格式,不需要任何坐标换算,只需把散落的 .txt 搬到
统一的输出目录。这是"接口相同、行为却不同"的典型 —— 它和 voc/coco 签名一致,但内部
什么都不解析。

⚠️ --classes 在这里的边界(重要,务必讲清):
    yolo 的 txt 每行只有数字 class_id、不含类名。所以 options.classes 在这里是
    【必填的命名信息】(没有它就没法写 yaml 的 names),而【不是过滤器】。
    本转换器原样搬运、不改内容、不重映射 id;因此对 yolo 源数据"删类"无法走 --classes
    —— 那样只会让 yaml 的 names 与 txt 里的 id 对不上(越界 / 张冠李戴)。
    yolo 源要删类,只能在源头重写 txt。
"""
from __future__ import annotations

import logging
import os
import shutil
from pathlib import Path
from typing import List

from od_platform.common.constants import AnnotationFormat, Task
from od_platform.data_pipeline.convert.registry import ConvertOptions, register

logger = logging.getLogger(__name__)

@register(AnnotationFormat.YOLO, supported_tasks=(Task.DETECT, Task.SEGMENT))
def convert_yolo(input_dir: Path, output_labels_dir: Path, options: ConvertOptions) -> List[str]:
    if not options.classes:
        # yolo 不含类名,必须由用户显式给出类别顺序,否则 yaml 的 names 无从填起。
        raise ValueError("yolo 格式不含类别名信息,必须通过 options.classes 显式提供类别顺序。")

    txt_files = sorted(input_dir.glob("*.txt"))
    if not txt_files:
        raise FileNotFoundError(f"在 {input_dir} 下未找到任何 yolo txt")

    output_labels_dir.mkdir(parents=True, exist_ok=True)
    for txt in txt_files:
        dst = output_labels_dir / txt.name
        try:                                    # 优先硬链接(零拷贝、省磁盘);跨盘会失败
            if dst.exists():
                dst.unlink()
            os.link(txt, dst)
        except OSError:                         # 跨文件系统等情况:退回普通复制
            shutil.copy2(txt, dst)

    logger.info("YOLO 直通: %d 个 txt 就位, %d 个类别", len(txt_files), len(options.classes))
    return list(options.classes)
```

注意第一行那个 `AnnotationFormat.YOLO`——它在 `constants.py` 里也得有。这是 `constants.py` 今天**第二次生长**(阶段 2 加了 `PASCAL_VOC`/`COCO`,现在补上 `YOLO`,`all()` 也跟着多一个)。

### 但要小心:接口长得一样 ≠ 行为处处一样

三个 converter 的签名完全一致 `(input_dir, out_labels_dir, options) -> list[str]`,所以调度层"一视同仁"地调它们。但**同一个 `--classes` 参数,对三种格式的意义并不相同**:

| 格式 | `--classes` 的作用 | 能用它"删类"吗 |
|---|---|---|
| `pascal_voc` | 白名单:不在名单的框**跳过**,并按名单**重排** `class_id` | ✅ 能(xml 里有类名,可按名字筛) |
| `coco` | 同上 | ✅ 能(json 里有类名) |
| `yolo` | **仅命名**:给那些数字 id 配上名字,**不过滤、不重映射** | ❌ 不能(删了会让 yaml 的 `names` 和 txt 的 id 对不上) |

> 💡 **金句**:**"接口签名相同,不代表行为处处相同。`--classes` 走 voc/coco 是过滤器,走 yolo 只是命名信息——这种差异要写在文档和代码注释的明处,而不是让用户自己踩坑。"** YOLO 源要删类,只能在源头重写 txt。(阶段 5 的报告会据此对 yolo 给出不同的建议文案。)

# 阶段 4:划分 train/val/test —— 朴素 → 撞墙② → 第二次撞上注册表

## 4.1 先写最朴素的随机划分 → 逼出一个"结果容器"

划分的朴素版很简单:把所有样本(每个样本是一对 `(图片路径, 标注路径)`)打乱,按 8:1:1 切三段。先写出来:

```python
# 朴素随机划分:打乱,切三段
import random
def naive_split(pairs, train_rate=0.8, val_rate=0.1, seed=42):
    rng = random.Random(seed)
    shuffled = sorted(pairs, key=lambda p: p[0].stem)   # 先定序,配合固定种子才可复现
    rng.shuffle(shuffled)
    n = len(shuffled); n_tr = round(n*train_rate); n_va = round(n*val_rate)
    return shuffled[:n_tr], shuffled[n_tr:n_tr+n_va], shuffled[n_tr+n_va:]
```

能跑。但马上有个问题:这个函数返回**三个列表**,调用方还得记住"哪个是 train、哪个是 val";而且后面写 yaml 时,还要用到"当初用了什么策略、什么种子、什么比例"——这些信息**散落在调用现场**,迟早丢。

与其返回裸的三元组,不如返回一个**带名字、连元数据一起打包**的结果容器 `SplitManifest`:

> 📄 **`apps/platform/src/od_platform/data_pipeline/split/manifest.py`** · 约 30 行
> **内容**:类型别名 `Pair = (image_path, label_path)`、`PairList`;数据类 `SplitManifest`(三组样本 + `train_rate/val_rate/test_rate/random_state/strategy` 元数据 + `summary()`)。
> **为什么这样设计**:让"划分结果"是一个**自带元数据**的对象——`yaml_writer` 不用再从别处拼凑"当初怎么切的"。`Pair` 用 `(图, 标)` 元组,是因为落盘时图和标要成对地搬。
> **现在为什么不做别的**:为什么不直接返回 `dict`?因为 `dataclass` 有字段名、有类型、IDE 能补全、改字段不易错;而且把"比例/种子/策略"焊进结果,天然服务于后面的可复现(阶段 5)。

```python
"""SplitManifest —— 一次划分的"结果载体"(三组样本 + 可复现元数据)。

为什么不直接返回三个列表,而要一个 dataclass:
    ① 三组有名字(train/val/test),调用方不必记"第几个是哪组";
    ② 把"当初怎么切的"(策略 / 种子 / 比例)和结果焊在一起 —— 这样写 yaml 时,
       yaml_writer 不用再从别处拼凑元数据,可复现性也自然落到产物里。
"""
from __future__ import annotations

from dataclasses import dataclass, field
from pathlib import Path
from typing import Dict, List, Tuple

# 一对样本 = (图片路径, 标注路径)。落盘时图和标要成对地搬,所以用元组绑在一起。
Pair = Tuple[Path, Path]
PairList = List[Pair]

@dataclass
class SplitManifest:
    # —— 三组样本 ——
    train: PairList = field(default_factory=list)
    val: PairList = field(default_factory=list)
    test: PairList = field(default_factory=list)
    # —— 可复现元数据(会被原样写进 yaml 的 odp_meta,供半年后回查实验)——
    train_rate: float = 0.8
    val_rate: float = 0.1
    test_rate: float = 0.1
    random_state: int = 42
    strategy: str = "random"

    def summary(self) -> Dict[str, int]:
        """各组计数 + 合计(给日志 / 测试断言用)。"""
        return {
            "train": len(self.train),
            "val": len(self.val),
            "test": len(self.test),
            "total": len(self.train) + len(self.val) + len(self.test),
        }
```

## 4.2 划分完要落盘 → materializer(还顺手解决"按数据集分桶"和"旧产物污染")

有了 manifest,下一步把三组样本真正**摆进磁盘目录**(ultralytics 要的是 `train/images`、`train/labels` 这样的目录结构)。这件事单独成一个模块:

> 📄 **`apps/platform/src/od_platform/data_pipeline/split/materializer.py`** · 约 45 行
> **内容**:`SplitOutputDirs`(六个目标目录:train/val/test × images/labels)+ 类方法 `for_dataset_root(root)` + `materialize(manifest, dirs)`(落盘前先清空,再硬链接/复制)。
> **为什么这样设计**:① **依赖注入**——`materialize` 不直接读 `paths.py` 全局常量,而是接收一个 `SplitOutputDirs`,这样测试能传临时目录(阶段 8 用得上)。② `for_dataset_root` 把六个子目录从**某数据集的派生根** `data/processed/<name>/` 组装出来——这就是我们**按数据集分桶**的落点:每个数据集独占一个根,多数据集互不覆盖(回扣[公约一])。③ 落盘前 `rmtree` 清空,**防止上一次划分的残留污染这次**。
> **现在为什么不做别的**:为什么 `paths.py` 不直接给这六个目录、非要 `for_dataset_root` 在这侧拼?因为"切成 6 个子目录"是 `data_pipeline` 的知识,不该塞进 `paths`(否则 `paths` 要反向依赖本模块,违反[公约三]的单向依赖)。`paths` 只回答"某数据集的根在哪"。

```python
"""materializer —— 把 SplitManifest 的三组样本真正"落盘"到 train/val/test 目录。

两个设计决定:
    ① 依赖注入(SplitOutputDirs):不直接读 paths.py 的全局常量,而是接收一个目录束。
       好处:测试时能传临时目录;也让"目录怎么组织"留在调用方,本模块只管搬运。
    ② 落盘前先清空 6 个目标目录:防止上一次划分的残留文件污染这一次(比如上次 val 有
       100 张、这次只有 80 张,不清就会混进 20 张旧的)。
"""
from __future__ import annotations

import logging
import os
import shutil
from dataclasses import dataclass
from pathlib import Path
from typing import Dict

from od_platform.data_pipeline.split.manifest import PairList, SplitManifest

logger = logging.getLogger(__name__)

@dataclass(frozen=True)
class SplitOutputDirs:
    """六个目标目录(train/val/test × images/labels)。"""
    train_images: Path
    train_labels: Path
    val_images: Path
    val_labels: Path
    test_images: Path
    test_labels: Path

    @classmethod
    def for_dataset_root(cls, root: Path) -> "SplitOutputDirs":
        """从某数据集的派生根 data/processed/<name>/ 组装出六个子目录。

        "切成 6 个子目录"是 data_pipeline 的知识,所以放在这里、而不是 paths.py
        (否则 paths 要反向依赖本模块,违反单向依赖)。paths 只回答"根在哪"。
        这也是"按数据集分桶"的落点:每个数据集一个 root,互不覆盖。
        """
        return cls(
            train_images=root / "train" / "images", train_labels=root / "train" / "labels",
            val_images=root / "val" / "images", val_labels=root / "val" / "labels",
            test_images=root / "test" / "images", test_labels=root / "test" / "labels",
        )

    def all_dirs(self):
        return (self.train_images, self.train_labels, self.val_images,
                self.val_labels, self.test_images, self.test_labels)

def _place(src: Path, dst: Path) -> None:
    """把一个文件放到目标位置:优先硬链接(零拷贝、省磁盘),跨盘失败退回复制。"""
    if dst.exists():
        dst.unlink()
    try:
        os.link(src, dst)
    except OSError:
        shutil.copy2(src, dst)

def _materialize_one(pairs: PairList, images_dir: Path, labels_dir: Path) -> int:
    images_dir.mkdir(parents=True, exist_ok=True)
    labels_dir.mkdir(parents=True, exist_ok=True)
    for img, lbl in pairs:                       # 图与标成对地搬,文件名保持不变
        _place(img, images_dir / img.name)
        _place(lbl, labels_dir / lbl.name)
    return len(pairs)

def materialize(manifest: SplitManifest, dirs: SplitOutputDirs) -> Dict[str, int]:
    """把三组样本落到对应目录,返回各组计数。"""
    for d in dirs.all_dirs():                    # ★ 先清旧划分产物,防数据污染
        if d.exists():
            shutil.rmtree(d)
    counts = {
        "train": _materialize_one(manifest.train, dirs.train_images, dirs.train_labels),
        "val": _materialize_one(manifest.val, dirs.val_images, dirs.val_labels),
        "test": _materialize_one(manifest.test, dirs.test_images, dirs.test_labels),
    }
    logger.info("materialize 完成: %s", counts)
    return counts
```

## 4.3 要喂给模型 → 写 dataset.yaml(并持久化"当初怎么切的")

ultralytics 训练吃一个 `dataset.yaml`(指明 train/val/test 目录、类名表)。我们顺手在里面塞一个 `odp_meta` 块,把划分元数据存下来:

> 📄 **`apps/platform/src/od_platform/data_pipeline/split/yaml_writer.py`** · 约 60 行
> **内容**:`write_dataset_yaml(yaml_path, *, dataset_root, classes, manifest, dataset_name, source_format, task)`——写 `path/train/val/test/names/nc` + 一个 `odp_meta`(schema 版本 / 数据集名 / 源格式 / task / 划分策略 / 种子 / 比例 / 计数)。
> **为什么这样设计**:`names` 用 `{下标: 类名}` 是 ultralytics 的格式;`odp_meta` 让**半年后回查实验**时还知道"当初用了什么策略 / 种子 / 比例"——这正是 manifest 携带元数据的回报。
> **现在为什么不做别的**:为什么自己拼 dict 而不用模板字符串?因为 `yaml.safe_dump` 能正确处理转义、缩进、CJK(`allow_unicode=True`),手拼字符串迟早在某个类名上翻车。

```python
"""yaml_writer —— 写出 ultralytics 训练用的 dataset.yaml,并附一个 odp_meta 块。

odp_meta 持久化"这次是怎么切的"(策略 / 种子 / 比例 / 计数)。它的价值:
    半年后回看某个实验,光有一堆图片你说不清"当初怎么划分的";有了 odp_meta,
    实验就可追溯、可复现。这也是 SplitManifest 一路携带元数据的最终回报。
"""
from __future__ import annotations

import logging
from pathlib import Path
from typing import List

import yaml

from od_platform.data_pipeline.split.manifest import SplitManifest

logger = logging.getLogger(__name__)

_SCHEMA_VERSION = 1   # odp_meta 的结构版本;将来字段变了,靠它向后兼容地识别

def write_dataset_yaml(
    yaml_path: Path,
    *,
    dataset_root: Path,
    classes: List[str],
    manifest: SplitManifest,
    dataset_name: str,
    source_format: str,
    task: str,
) -> None:
    """写出 ultralytics 可直接吃的 dataset yaml(names/nc/train/val/test)+ odp_meta。"""
    yaml_path.parent.mkdir(parents=True, exist_ok=True)
    doc = {
        "path": str(dataset_root),               # 数据集根;下面三项是相对它的子路径
        "train": "train/images",
        "val": "val/images",
        "test": "test/images",
        "names": {i: name for i, name in enumerate(classes)},  # ultralytics 要 {下标: 类名}
        "nc": len(classes),
        "odp_meta": {                            # 我们自己的可复现元数据(ultralytics 会忽略它)
            "schema_version": _SCHEMA_VERSION,
            "dataset_name": dataset_name,
            "source_format": source_format,
            "task": task,
            "split": {
                "strategy": manifest.strategy,
                "random_state": manifest.random_state,
                "rates": {
                    "train": round(manifest.train_rate, 6),
                    "val": round(manifest.val_rate, 6),
                    "test": round(manifest.test_rate, 6),
                },
                "counts": manifest.summary(),
            },
        },
    }
    # 用 yaml.safe_dump 而非手拼字符串:它能正确处理缩进、转义,allow_unicode 让中文类名不被转义。
    yaml_path.write_text(yaml.safe_dump(doc, allow_unicode=True, sort_keys=False), encoding="utf-8")
    logger.info("已写入 dataset yaml: %s", yaml_path)
```

到这,"随机划分 → 落盘 → 写 yaml"已能端到端跑通。但朴素的"纯随机",藏着一个能让训练白干的坑。

## 4.4 🧱 撞墙②:纯随机,会把稀有类划进 0 张

回到我们故意造的不平衡数据:62 张图里,`反光衣` 只在 12 张出现。用纯随机切 8:1:1,看看 `反光衣` 落进了哪几组(已验证):

```text
策略 random                 summary={'train': 50, 'val': 6, 'test': 6}   反光衣={'train': 10, 'val': 2, 'test': 0}
```

**`反光衣` 在 test 里是 0 张。** 后果很实在:模型在测试集上**永远见不到** `反光衣`,你以为"测过了",其实这个类的测试指标根本不存在;要是它恰好落进 val 也 0 张,训练时连早停 / 调参的依据都没有。**随机,对稀有类是不公平的。**

我们想要的是:**让每个类都按比例铺到三组里,稀有类不至于整体消失。** 这又是一个"多实现"问题——除了 `random`,还要 `stratified`(主类别分层)、`stratified_multilabel`(多标签分层)……格式那边怎么解决多实现的?**注册表。** 这里一模一样。

## 4.5 修复:第二张注册表 —— 而且现在才把扫描逻辑抽出来

划分策略的多实现,和阶段 2 的格式多实现是**同一个模子**:一张表(策略名 → 策略函数)、`@register_strategy` 让每个策略自登记、自动发现扫描 `strategies/` 目录。

写到这儿你会发现:**"扫描一个目录、逐个 import 触发 @register"这段逻辑,convert 那张表已经写过一遍了**(阶段 2 内联在 `registry._lazy_init` 里)。现在 split 这第二张表又要原样来一遍——**这就是"第二次出现"。** 按我们的纪律(撞到第二次才抽象),现在把它抽成一个公共件:

> 📄 **`apps/platform/src/od_platform/common/registry_utils.py`** · 约 15 行 —— 一个函数 `import_submodules(package)`:扫 `package` 下所有非下划线子模块、逐个 import,触发其中的 `@register`。
> **为什么是现在**:阶段 2 只有一个用例(convert),抽出来是没对象的过度设计;直到 split 这第二个用例出现,"抽出共享"才**真的省事**——抽完之后,两张表的 `_lazy_init` 都只剩一行调用。**这就是"第二次才抽象"的字面落地。**

```python
"""注册表通用工具:自动发现并 import 一个包下的所有实现模块,触发其中的 @register 副作用。

它解决的具体问题(阶段 2.5 的"空表"撞墙):
    @register 这行登记,是在"实现文件被 import 的那一刻"才执行的;而 Python 不会执行
    你没 import 的文件。所以光有 @register 还不够——必须有人在"用表"之前,把 converters/
    (或 strategies/)目录下的实现文件都 import 一遍,那些 @register 才会真正往表里写。
    本函数就干这件"开门时把它们都叫醒"的事。

为什么抽成公共件(阶段 4,"第二次才抽象"):
    convert 那张表先把这段扫描逻辑内联在自己的 _lazy_init 里(只有一个用例时,抽出来是
    没对象的过度设计)。直到 split 第二张表也要原样来一遍,"抽出共享"才真的省事——
    抽完之后,两张表的 _lazy_init 都只剩一行 import_submodules(...)。
"""
from __future__ import annotations

import importlib
import pkgutil
from types import ModuleType

def import_submodules(package: ModuleType) -> None:
    """import package 下所有【非下划线】子模块,触发其中的 @register 注册。

    Args:
        package: 已 import 的包对象(如 converters / strategies)。用它的 __path__ 扫目录。

    约定:下划线开头的模块(如 strategies/_common.py)是"公用纯函数",不是实现,被跳过。
    """
    for m in pkgutil.iter_modules(package.__path__):
        if not m.name.startswith("_"):
            importlib.import_module(f"{package.__name__}.{m.name}")
```

抽完之后,**回头把 convert 那张表也改成调它**(原先内联的 `pkgutil` 循环换成一行 `import_submodules(converters)`),新的 split 表同样调它。两张表从此共用同一段扫描逻辑:

```python
# convert/registry.py 的 _lazy_init(改造后)        # split/strategy_registry.py 的 _lazy_init(新建)
from od_platform.common.registry_utils import import_submodules
from od_platform.data_pipeline.convert import converters    # ……split 这边 import 的是 strategies
import_submodules(converters)                               # 两边都只剩这一行
```

现在搭 split 的策略注册表(结构和 `convert.registry` 一一对应:`SplitOptions` 参数包、`StrategyEntry`(函数 + `requires_labels` 能力声明)、`register_strategy`、`get_strategy` / `list_strategies`、`_lazy_init`):

> 📄 **`apps/platform/src/od_platform/data_pipeline/split/strategy_registry.py`** · 约 55 行
> **内容**:见上;能力声明从"支持哪些 task"换成 `requires_labels`(这个策略需不需要"每张图的类别")。
> **为什么这样设计**:`SplitOptions.labels_per_image` 是 `{图: [类别名]}`;**指挥家会对所有策略统一构建它**,策略自取自用——这样指挥家**不需要认识任何具体策略名**(随机用不到它就忽略,分层用得到就读)。`requires_labels` 让调度层在分发前就能 fail-fast(需要标签的策略没拿到标签,当场报清楚)。

```python
"""split 子系统的划分策略注册表 + 统一参数包。

它与 convert/registry.py 是【同一个模子】的另一次浇筑:
    convert 那张表    →  这张表
    @register          →  @register_strategy
    supported_tasks    →  requires_labels(能力声明换了个维度)
    service.py 调度     →  splitter.py 调度
    converters/*.py    →  strategies/*.py
所以"加一种划分策略"= 在 strategies/ 加一个文件,本文件和 splitter.py 永不改动。
"""
from __future__ import annotations

import logging
from dataclasses import dataclass, field
from typing import Callable, Dict, List, Optional, Tuple

from od_platform.common.constants import DEFAULT_RANDOM_STATE
from od_platform.data_pipeline.split.manifest import PairList, SplitManifest

logger = logging.getLogger(__name__)

@dataclass
class SplitOptions:
    """所有划分策略共用的参数包(对应 convert 的 ConvertOptions)。

    labels_per_image: {图片stem: [类别名, ...]}。语义同 ConvertOptions.classes 的 None/[]:
        None = 没提供;{} = 每张图都没类别。
        ★ 指挥家对【所有】策略统一构建它,由策略自取自用 —— 这样指挥家不需要认识任何
          具体策略名(随机策略用不到就忽略,分层策略用得到就读)。这是注册表的"开闭"
          延伸到编排层:加新策略,指挥家一行不改。
    group_per_image: {图片stem: 组名}。预留给"按组划分"(防同段视频帧泄漏,见课后练习)。
    """
    train_rate: float = 0.8
    val_rate: float = 0.1
    random_state: int = DEFAULT_RANDOM_STATE
    labels_per_image: Optional[Dict[str, List[str]]] = field(default=None)
    group_per_image: Optional[Dict[str, str]] = field(default=None)

# 一个划分策略的统一类型:吃 (样本对列表, 参数包),返回一份 SplitManifest。
StrategyFunc = Callable[[PairList, SplitOptions], SplitManifest]

@dataclass(frozen=True)
class StrategyEntry:
    """注册表里一条记录:策略函数 + 它的能力声明。"""
    func: StrategyFunc
    requires_labels: bool = False
    # requires_labels:该策略是否依赖 labels_per_image。调度层据此提前 fail-fast
    # (需要标签却没拿到 → 当场报清楚,而不是进了策略内部才炸难懂的异常)。

_STRATEGY_REGISTRY: Dict[str, StrategyEntry] = {}

def register_strategy(name: str, *, requires_labels: bool = False):
    """装饰器:把划分策略登记进表。等价于手写 _STRATEGY_REGISTRY[name] = StrategyEntry(...)。"""
    def decorator(func: StrategyFunc) -> StrategyFunc:
        if name in _STRATEGY_REGISTRY:
            logger.warning("划分策略 %s 被重复注册,后者覆盖前者", name)
        _STRATEGY_REGISTRY[name] = StrategyEntry(func=func, requires_labels=requires_labels)
        return func
    return decorator

def get_strategy(name: str) -> StrategyEntry:
    """按名取策略条目(先触发自动发现)。Raises ValueError 未注册的策略。"""
    _lazy_init()
    if name not in _STRATEGY_REGISTRY:
        raise ValueError(f"未注册的划分策略: {name!r}。已注册: {sorted(_STRATEGY_REGISTRY)}")
    return _STRATEGY_REGISTRY[name]

def list_strategies() -> Tuple[str, ...]:
    """当前已注册的策略名(先触发自动发现)。"""
    _lazy_init()
    return tuple(sorted(_STRATEGY_REGISTRY))

_LAZY_INITIALIZED = False

def _lazy_init() -> None:
    """扫描 strategies/*.py 触发 @register_strategy。

    复用 convert 那张表抽出来的同一段扫描逻辑(import_submodules)—— 两张表共用一份实现,
    这正是"第二次才抽象"抽出来的回报。标志位同样放在 import 全部成功之后。
    """
    global _LAZY_INITIALIZED
    if _LAZY_INITIALIZED:
        return
    from od_platform.common.registry_utils import import_submodules
    from od_platform.data_pipeline.split import strategies
    import_submodules(strategies)
    _LAZY_INITIALIZED = True
```

策略们公用的纯计算(校验比例、按比例算三段数量、带种子洗牌)收进一个**私有** `_common.py`(下划线开头,所以 `import_submodules` 会跳过它——它不是策略):

> 📄 **`split/strategies/_common.py`** · 约 35 行 —— `validate_rates`(校验并返回 test_rate)、`three_way_counts`(四舍五入+钳位,保证求和=n、极小 n 自然退化)、`seeded_shuffled`(用传入的 `Random` 洗牌,不碰全局随机)。**无 IO、无随机副作用**,纯函数,好测。

```python
"""划分策略公用的纯函数(下划线开头 → 自动发现会跳过它,因为它不是一个"策略")。

设计原则:无 IO、无随机副作用。随机由【调用方传入的 Random 实例】控制,不碰全局 random
—— 这样同一个种子在哪里调用都得到同一序列,是可复现性的基石。
"""
from __future__ import annotations

import random
from typing import List, Sequence, Tuple, TypeVar

from od_platform.common.constants import RATE_EPSILON

T = TypeVar("T")

def validate_rates(train_rate: float, val_rate: float) -> float:
    """校验比例合法,并返回推算出的 test_rate(= 1 - train - val)。

    Raises:
        ValueError: 任一比例越界。用 RATE_EPSILON 吸收浮点误差,避免正常的 70/30 被误杀。
    """
    test_rate = 1.0 - train_rate - val_rate
    if not (0 <= train_rate <= 1 and 0 <= val_rate <= 1 and -RATE_EPSILON <= test_rate <= 1):
        raise ValueError(f"比例越界: train={train_rate}, val={val_rate}, test={test_rate:.4f}")
    return max(0.0, test_rate)               # 钳掉 -5e-17 这种浮点噪声,保证非负

def three_way_counts(n: int, train_rate: float, val_rate: float) -> Tuple[int, int, int]:
    """把 n 个样本按比例切成 (n_train, n_val, n_test)。

    四舍五入 + 钳位,保证三者非负且求和恰好等于 n(不会因取整丢样本)。
    极小 n 自然退化:n=1 → 全进 train;n=2 → train=2(val/test 摊不到,符合预期)。
    """
    n_train = int(round(n * train_rate))
    n_val = int(round(n * val_rate))
    n_train = max(0, min(n_train, n))
    n_val = max(0, min(n_val, n - n_train))
    return n_train, n_val, n - n_train - n_val   # test 拿剩下的,保证总和 = n

def seeded_shuffled(seq: Sequence[T], rng: random.Random) -> List[T]:
    """返回 seq 的洗牌副本(不改原序列;随机性完全由传入的 rng 决定)。"""
    out = list(seq)
    rng.shuffle(out)
    return out
```

> 📌 **`RATE_EPSILON` 哪来的?** `1.0 - 0.7 - 0.3` 在浮点里不是 0,而是 `5.55e-17`。`constants.py` 此刻长出 `RATE_EPSILON = 1e-6` 来吸收这种浮点误差——又一个"被具体问题逼出来的常量"。

> 📄 **`split/strategies/random_split.py`** · 约 20 行 —— `@register_strategy("random", requires_labels=False)`;`sorted` 定序后带种子洗牌、切三段。最朴素,不需要标签。

```python
"""L0 策略:纯随机划分(纯 Python,不依赖 sklearn)。

最朴素的基线。它对稀有类不公平 —— 这正是课程里"撞墙②"的来源:某个只在少数图里出现的
类,随机一切就可能在 val/test 落到 0 张。需要均衡时改用 stratified / multilabel。
"""
from __future__ import annotations

import random

from od_platform.common.constants import SplitStrategy
from od_platform.data_pipeline.split.manifest import PairList, SplitManifest
from od_platform.data_pipeline.split.strategies._common import (
    seeded_shuffled, three_way_counts, validate_rates,
)
from od_platform.data_pipeline.split.strategy_registry import SplitOptions, register_strategy

@register_strategy(SplitStrategy.RANDOM, requires_labels=False)   # 随机不需要类别信息
def random_split(pairs: PairList, options: SplitOptions) -> SplitManifest:
    test_rate = validate_rates(options.train_rate, options.val_rate)
    manifest = SplitManifest(
        train_rate=options.train_rate, val_rate=options.val_rate, test_rate=test_rate,
        random_state=options.random_state, strategy=SplitStrategy.RANDOM,
    )
    n = len(pairs)
    if n == 0:
        return manifest

    rng = random.Random(options.random_state)
    # 先 sorted 把输入顺序固定下来,再用固定种子洗牌 —— 两者缺一不可,否则不可复现
    # (光固定种子,若输入顺序本身随机,结果照样会变)。
    shuffled = seeded_shuffled(sorted(pairs, key=lambda p: p[0].stem), rng)
    n_train, n_val, _ = three_way_counts(n, options.train_rate, options.val_rate)
    manifest.train = shuffled[:n_train]
    manifest.val = shuffled[n_train:n_train + n_val]
    manifest.test = shuffled[n_train + n_val:]
    return manifest
```

> 📄 **`split/strategies/stratified_split.py`** · 约 45 行 —— `@register_strategy("stratified", requires_labels=True)`。**主类别分层**:每张图取"出现最多的类"作分层键,按键分桶,每桶内部各自按比例切再合并 ⇒ 每个主类别都按比例进三组。
> **为什么这样设计 / 现在为什么不做别的**:① **不崩**——某分层桶太小(1~2 张)时,该桶自然落进 train、不阻断其它桶(原始实现遇到桶 <2 直接 `ValueError` 炸掉整条线,这里改成只把它记进 `starved` 警告)。② **诚实声明盲点**——主类别分层只看"主类别",一个"从不是任何图主类别"的稀有类仍得不到保护,这种情况要用下面的多标签分层。把局限写在 docstring 里,别让用户以为分层是万能的。

```python
"""L1 策略:主类别分层划分(纯 Python,不依赖 sklearn)。

做法:给每张图取一个"分层键"= 它出现次数最多的类(并列取首次出现);按分层键分桶,
      每个桶各自按 train/val/test 比例切,再合并。⇒ 每个"主类别"都按比例铺到三组,
      稀有类不至于整体消失(解掉撞墙②)。

两点工程取舍(写进注释,免得学员误会"分层=万能"):
  · 不崩:某分层桶太小(1~2 张)时,该桶按比例自然落进 train、不阻断其它桶;是否丢弃这个
    稀有类,交给 report 提醒 + 用户用 --classes 决定(对比:sklearn 的 stratify 在某类 <2 时
    直接报错,会一刀炸掉整条流水线)。
  · 盲点(诚实声明):主类别分层只看"主类别",一个【从来不是任何图主类别】的次要稀有类
    得不到分层保护 —— 要同时平衡所有类,用 stratified_multilabel。
"""
from __future__ import annotations

import logging
import random
from collections import Counter, defaultdict
from typing import Dict, List

from od_platform.common.constants import SplitStrategy
from od_platform.data_pipeline.split.manifest import PairList, SplitManifest
from od_platform.data_pipeline.split.strategies._common import (
    seeded_shuffled, three_way_counts, validate_rates,
)
from od_platform.data_pipeline.split.strategy_registry import SplitOptions, register_strategy

logger = logging.getLogger(__name__)

_EMPTY_KEY = "__empty__"   # 无标注图像归到这个分层桶

def _primary_class(class_names: List[str]) -> str:
    """分层键 = 出现次数最多的类。并列取首次出现(Counter 保留插入序 → 跨运行稳定)。"""
    if not class_names:
        return _EMPTY_KEY
    return Counter(class_names).most_common(1)[0][0]

@register_strategy(SplitStrategy.STRATIFIED, requires_labels=True)   # 需要每张图的类别
def stratified_split(pairs: PairList, options: SplitOptions) -> SplitManifest:
    test_rate = validate_rates(options.train_rate, options.val_rate)
    if options.labels_per_image is None:
        raise ValueError("stratified 策略需要 labels_per_image,但收到 None。")

    manifest = SplitManifest(
        train_rate=options.train_rate, val_rate=options.val_rate, test_rate=test_rate,
        random_state=options.random_state, strategy=SplitStrategy.STRATIFIED,
    )
    if not pairs:
        return manifest

    labels = options.labels_per_image
    # 1) 分桶:分层键 → 该键下的样本对。sorted 是复现前提。
    buckets: Dict[str, PairList] = defaultdict(list)
    for img, lbl in sorted(pairs, key=lambda p: p[0].stem):
        buckets[_primary_class(labels.get(img.stem, []))].append((img, lbl))

    rng = random.Random(options.random_state)
    starved: List[str] = []                  # 记录"在 val/test 摊不到样本"的主类别,稍后统一警告
    # 2) 每个桶内部各自按比例切(按 key 排序保证确定性)。
    for key in sorted(buckets.keys()):
        bucket = seeded_shuffled(buckets[key], rng)
        nb = len(bucket)
        n_tr, n_va, n_te = three_way_counts(nb, options.train_rate, options.val_rate)
        if key != _EMPTY_KEY and (n_va == 0 or n_te == 0):
            starved.append(f"{key}({nb}图)")
        manifest.train.extend(bucket[:n_tr])
        manifest.val.extend(bucket[n_tr:n_tr + n_va])
        manifest.test.extend(bucket[n_tr + n_va:])

    if starved:
        logger.warning(
            "以下主类别样本过少,在 val/test 分不到样本(评估对它失真): %s。"
            "如需覆盖,请补样本、改用 stratified_multilabel,或用 --classes 排除。",
            ", ".join(starved),
        )
    return manifest
```

> 📄 **`split/strategies/stratified_multilabel.py`** · 约 80 行 —— `@register_strategy("stratified_multilabel", requires_labels=True)`。**多标签迭代分层**(算法出自 Sechidis et al. 2011):不把"一图多类"塌缩成主类别,而是每步挑"剩余最稀有的类",优先把它的样本投进"最缺它"的子集 ⇒ 所有类(含次要稀有类)都尽量按比例铺到三组。
> **现在为什么不做别的**:为什么**自己写**、不装 `iterative-stratification`?① 算法本身就 ~80 行,自己写省一个外部依赖;② 那个库"官方只测到 Python 3.9",是个隐患;③ `sklearn` 的 `stratify=` 在某类 <2 时**直接报错**,而我们要的是"尽力分配且不崩"。**这是"按需自研、不盲目引依赖"的一个真实判断,值得讲给学员。**

```python
"""L1+ 策略:多标签迭代分层(自实现,不依赖第三方库)。

为什么自己写、不引 iterative-stratification:
    ① 算法本身就 ~80 行,自己写省掉一个外部依赖;
    ② 那个库"官方只测到 Python 3.9",是潜在隐患;
    ③ sklearn 的 stratify 在某类 <2 时直接报错,而我们要的是"尽力分配且不崩"。
    这是一次"按需自研、不盲目引依赖"的真实工程判断。

核心思想(一阶迭代分层,出自 Sechidis/Tsoumakas/Vlahavas 2011):
    不把"一图多类"硬塌缩成主类别,而是把每张图当一个多标签样本,对 train/val/test 做贪心
    分配 —— 每一步挑出"剩余样本最少的那个类"(最稀有),优先把它的样本投进"最缺这个类"
    的子集。这样所有类(包括次要稀有类)都尽量按比例铺到三组。
    极稀有类(只有 1~2 张图)仍无法真进三组,但不会崩,且 report 会单独提醒。
"""
from __future__ import annotations

import logging
import random
from collections import defaultdict
from typing import Dict, List, Sequence, Set

from od_platform.common.constants import SplitStrategy
from od_platform.data_pipeline.split.manifest import PairList, SplitManifest
from od_platform.data_pipeline.split.strategies._common import validate_rates
from od_platform.data_pipeline.split.strategy_registry import SplitOptions, register_strategy

logger = logging.getLogger(__name__)
_EPS = 1e-9   # 比较浮点期望值时的容差

def _argmax_tiebreak(primary: Sequence[float], secondary: Sequence[float], rng: random.Random) -> int:
    """返回使 primary 最大的下标;并列时看 secondary 最大;再并列则(seeded)随机。"""
    pmax = max(primary)
    cand = [j for j, v in enumerate(primary) if v >= pmax - _EPS]
    if len(cand) > 1:
        smax = max(secondary[j] for j in cand)
        cand = [j for j in cand if secondary[j] >= smax - _EPS]
    return rng.choice(sorted(cand)) if len(cand) > 1 else cand[0]

def iterative_stratify(sample_labels: List[Set[str]], proportions: Sequence[float], random_state: int) -> List[int]:
    """把 N 个多标签样本分到 len(proportions) 个子集,尽量保持每个标签的占比。

    Returns:
        fold[i] = 第 i 个样本被分到的子集下标。
    """
    n = len(sample_labels)
    k = len(proportions)
    fold = [-1] * n
    if n == 0:
        return fold

    rng = random.Random(random_state)
    # 每个标签 → 仍未分配且含该标签的样本下标集合(随分配进行不断缩小)
    label_to_samples: Dict[str, Set[int]] = defaultdict(set)
    for i, labs in enumerate(sample_labels):
        for l in labs:
            label_to_samples[l].add(i)
    # 期望:每个子集还"想要"多少样本 / 每个标签在每个子集还想要多少(浮点,随分配递减)
    desired = [p * n for p in proportions]
    desired_l: Dict[str, List[float]] = {
        l: [p * len(s) for p in proportions] for l, s in label_to_samples.items()
    }

    remaining = set(range(n))
    while remaining:
        # 在"还有样本的标签"里挑剩余最少的(最稀有);并列按名字定序后随机。
        candidates = [l for l, s in label_to_samples.items() if s]
        if not candidates:
            break                            # 只剩"无标签"样本,留到下面统一处理
        min_count = min(len(label_to_samples[l]) for l in candidates)
        tied = sorted(l for l in candidates if len(label_to_samples[l]) == min_count)
        l_star = rng.choice(tied)
        # 把这个最稀有类当前所有剩余样本逐个安置进"最缺它"的子集
        for i in sorted(label_to_samples[l_star]):
            if i not in remaining:
                continue
            j = _argmax_tiebreak(desired_l[l_star], desired, rng)
            fold[i] = j
            remaining.discard(i)
            for m in sample_labels[i]:        # 该样本所有标签的期望都要相应扣减
                desired_l[m][j] -= 1
                label_to_samples[m].discard(i)
            desired[j] -= 1

    # 无标签样本:按各子集剩余期望从大到小填
    for i in sorted(remaining):
        j = _argmax_tiebreak(desired, [0.0] * k, rng)
        fold[i] = j
        desired[j] -= 1
    return fold

@register_strategy(SplitStrategy.STRATIFIED_MULTILABEL, requires_labels=True)
def stratified_multilabel_split(pairs: PairList, options: SplitOptions) -> SplitManifest:
    test_rate = validate_rates(options.train_rate, options.val_rate)
    if options.labels_per_image is None:
        raise ValueError("stratified_multilabel 策略需要 labels_per_image,但收到 None。")

    manifest = SplitManifest(
        train_rate=options.train_rate, val_rate=options.val_rate, test_rate=test_rate,
        random_state=options.random_state, strategy=SplitStrategy.STRATIFIED_MULTILABEL,
    )
    if not pairs:
        return manifest

    ordered = sorted(pairs, key=lambda p: p[0].stem)     # 复现前提
    labels = options.labels_per_image
    sample_labels: List[Set[str]] = [set(labels.get(img.stem, [])) for img, _ in ordered]
    fold = iterative_stratify(
        sample_labels, [options.train_rate, options.val_rate, test_rate], options.random_state
    )
    buckets = (manifest.train, manifest.val, manifest.test)
    for pair, j in zip(ordered, fold):
        buckets[j].append(pair)
    return manifest
```

```python
"""split 调度层 —— 查策略表、能力驱动 fail-fast、分发。与 convert.service 同构,永不增长。"""

logger = logging.getLogger(__name__)

def split_pairs(
    pairs: PairList,
    train_rate: float = 0.8,
    val_rate: float = 0.1,
    random_state: int = DEFAULT_RANDOM_STATE,
    *,
    strategy: str = DEFAULT_SPLIT_STRATEGY,
    labels_per_image: Optional[Dict[str, List[str]]] = None,
    group_per_image: Optional[Dict[str, str]] = None,
) -> SplitManifest:
    """把样本对按 strategy 划分成 train/val/test。

    Raises:
        ValueError: 策略未注册 / 需要标签的策略没拿到标签 / 比例越界(在策略内部校验)。
    """
    entry = get_strategy(strategy)
    # 能力声明驱动的 fail-fast:需要标签的策略(stratified*)没拿到标签,当场报清楚。
    if entry.requires_labels and labels_per_image is None:

    options = SplitOptions(
        train_rate=train_rate, val_rate=val_rate, random_state=random_state,
        labels_per_image=labels_per_image, group_per_image=group_per_image,
    )
    return entry.func(pairs, options)
```

## 5.1 可复现:一条贯穿始终的独立纪律

阶段 4 的 Checkpoint 里有一行 `可复现(同种子两次): True`。它不是偶然——可复现是我们从一开始就埋好的纪律,由三件事共同保证:

1. **固定随机种子**:`random_state` 默认 `42`(`constants.DEFAULT_RANDOM_STATE`),所有洗牌都用 `random.Random(seed)` 这个**局部** rng,绝不碰全局 `random`(否则别处一调用 `random.random()` 就把你的序列带歪了)。
2. **输入先定序**:每个策略都先 `sorted(pairs, key=lambda p: p[0].stem)` 再洗牌。**只有固定种子还不够**——如果输入顺序本身不稳定(比如 `glob` 在不同机器上返回顺序不同),同一个种子也会洗出不同结果。定序 + 固定种子,才真正可复现。
3. **把"怎么切的"写进产物**:`yaml` 里的 `odp_meta.split` 存了 `strategy / random_state / rates / counts`。

> 💡 **金句**:**"`data/processed/` 本身不会自动可复现——它只是一次划分的快照。可复现性活在'固定种子 + 输入定序 + 元数据落盘'里。半年后想复现这次实验,你查的是 yaml 里的 `odp_meta`,不是去比对那堆图片。"**

> 📌 这也解释了 D2 为什么把 `data/processed/` 归为"派生可再生"——只要 `raw/` + `odp_meta` 还在,这份 processed 随时能一模一样地重算出来,所以 `odp-reset` 删它毫无心理负担(回扣 D0 决定 5 / D2)。

## 5.2 类别平衡报告:开跑前先照一张"体检表"

撞墙②让我们看到稀有类的危险。但"哪个类稀有、稀有到什么程度",不该等划分完才发现——应该在**转换之后、划分之前**先打一份报告,让用户心里有数。

这里要立一条**铁规矩**:

> **检查 ≠ 过滤。报告只做三件事:算账、打表、提醒。它绝不自动删类、绝不改任何数据。** 删类是用户的决定(走转换器已有的 `--classes` 白名单);报告最多在支持的格式上,给一行**可复制的 `--classes` 建议**。

报告看**两个维度**(这区分很关键,要讲清):

- **图(image)**:决定"**能不能切**"——划分是按图做的,某类的图太少,就进不了 val/test(这正是撞墙②)。
- **框(box)**:决定"**学不学得会**"——模型从框里学,loss 被框数主导;某类框太少,再怎么分也学不好。

> 📄 **`apps/platform/src/od_platform/data_pipeline/report.py`** · 约 120 行
> **内容**:`ClassStat` / `ClassBalanceReport`(数据类)、`analyze_class_balance(labels_per_image, classes, train_rate, val_rate)`(纯函数:算每类图数 / 框数 / 占比 / 状态)、`render_balance_report(report, source_format)`(渲染成"(行文本, 是否警告)"列表)。
> **为什么这样设计**:① **纯函数 + 字符串渲染,CI 友好**——不交互、不阻断,是否因某类太少而停下是 orchestrator/用户的策略,不是报告的事。② **"有用地板"** `≈ 1/min(val,test)`:低于这个图数,期望在最小子集里连 1 张都摊不到。③ 图占比是**普及度**(会重叠,不求和到 100%),框占比是**实例份额**(求和到 100%)——分母不同,别混。④ 表格走 D1 的 `string_utils`(CJK 显示宽度感知),中文类名不会错位。
> **现在为什么不做别的**:为什么不在报告里直接把弱类删了再返回?因为那是**偷偷改数据**——用户可能本来就想训练这个稀有类。报告的职责到"提醒 + 建议"为止,决定权留给用户。

```python
"""类别平衡性报告 —— 只算账、打表、提醒。绝不过滤、绝不改数据。

核心边界(本课反复强调):检查 ≠ 过滤。
    本模块只产出一份只读报告 + (在支持的格式上)一行"可复制的 --classes 建议"。
    删不删类是【用户】的决定,走转换器已有的 --classes 白名单 —— 报告不替用户做主。
    它也 CI 友好:纯函数 + 字符串渲染,不交互、不阻断;是否因某类太少而停下,是
    orchestrator / 用户的策略选择,不是本模块的事。

两个维度(务必区分):
    · 图(image):决定"能不能切" —— 划分是按图做的,某类的图太少就进不了 val/test。
    · 框(box)  :决定"学不学得会" —— 模型从框里学,loss 被框数主导。
    占比的分母也不同:图占比是"普及度"(会重叠,不求和到 100%);框占比是"实例份额"
    (求和到 100%)。
"""
from __future__ import annotations

import math
from collections import Counter
from dataclasses import dataclass
from typing import Dict, List, Tuple

from od_platform.common.constants import (
    CLASS_MIN_BOX_SHARE, CLASS_MIN_BOXES_WARN, CLASS_MIN_IMAGES_HARD, AnnotationFormat,
)
from od_platform.common.string_utils import (
    format_table_row, format_table_separator, get_display_width,
)

# 哪些格式能用 --classes 删类:voc/coco 有类名 → 能过滤+重排;yolo 只命名 → 不能删。
_CLASSES_FILTERABLE = {AnnotationFormat.PASCAL_VOC, AnnotationFormat.COCO}

_OK = "OK"
_BOTH = "⚠️ 严重不足(图/框双低)"
_BOX = "⚠️ 框数偏低"
_IMG = "⚠️ 图数偏低"

@dataclass(frozen=True)
class ClassStat:
    """单个类别的统计行。"""
    name: str
    image_count: int
    box_count: int
    image_pct: float       # image_count / total_images(普及度,不求和到 1)
    box_pct: float         # box_count / total_boxes(实例份额,求和到 1)
    status: str

    @property
    def ok(self) -> bool:
        return self.status == _OK

@dataclass(frozen=True)
class ClassBalanceReport:
    """整份报告:每类统计 + 总量 + "有用地板"。"""
    stats: List[ClassStat]
    total_images: int
    total_boxes: int
    usefulness_img_floor: int   # 图数低于此,大概率进不了最小的子集

    @property
    def flagged(self) -> List[ClassStat]:
        return [s for s in self.stats if not s.ok]

    @property
    def has_warnings(self) -> bool:
        return bool(self.flagged)

    def keeper_classes(self) -> List[str]:
        """状态 OK 的类(保留原顺序)—— 用于生成 --classes 建议行。"""
        return [s.name for s in self.stats if s.ok]

def analyze_class_balance(
    labels_per_image: Dict[str, List[str]],
    classes: List[str],
    train_rate: float,
    val_rate: float,
) -> ClassBalanceReport:
    """纯函数:由 {图: [类别名,...]} + 类别表 + 比例,算出每类的图/框分布与状态。"""
    total_images = len(labels_per_image)
    test_rate = max(0.0, 1.0 - train_rate - val_rate)

    image_count: Dict[str, int] = {c: 0 for c in classes}
    box_count: Dict[str, int] = {c: 0 for c in classes}
    for labs in labels_per_image.values():
        for name, k in Counter(labs).items():
            if name in box_count:
                box_count[name] += k          # 框数 = 出现次数(同图同类多次计多次)
                image_count[name] += 1         # 图数 = 含该类的图 +1(同图同类只算一次)
    total_boxes = sum(box_count.values())

    # "有用地板":想在最小子集里至少摊到 1 张,需要的图数 ≈ 1 / min(val,test)。
    smallest = min(r for r in (val_rate, test_rate) if r > 0) if (val_rate > 0 or test_rate > 0) else 0.0
    floor = max(CLASS_MIN_IMAGES_HARD, math.ceil(1.0 / smallest)) if smallest > 0 else CLASS_MIN_IMAGES_HARD

    stats: List[ClassStat] = []
    for c in classes:
        ic, bc = image_count[c], box_count[c]
        img_starved = ic < floor
        box_share = (bc / total_boxes) if total_boxes else 0.0
        box_starved = bc < CLASS_MIN_BOXES_WARN or box_share < CLASS_MIN_BOX_SHARE
        status = _BOTH if (img_starved and box_starved) else _BOX if box_starved else _IMG if img_starved else _OK
        stats.append(ClassStat(
            name=c, image_count=ic, box_count=bc,
            image_pct=(ic / total_images) if total_images else 0.0,
            box_pct=box_share, status=status,
        ))

    return ClassBalanceReport(
        stats=stats, total_images=total_images, total_boxes=total_boxes,
        usefulness_img_floor=floor,
    )

def render_balance_report(report: ClassBalanceReport, source_format: str) -> List[Tuple[str, bool]]:
    """把报告渲染成 [(行文本, 是否警告), ...]。只读,不改任何东西。

    偏弱类别的数据行 is_warning=True,调用方(如指挥家)可用 WARNING 级别高亮它们。
    列宽用 D1 的 CJK 宽度工具按"显示宽度"计算,中文类名不会错位。
    """
    flagged = {s.name for s in report.flagged}

    # 列宽 = max(表头显示宽, 各数据显示宽) + 余量
    name_w = max(get_display_width("类别"), max((get_display_width(s.name) for s in report.stats), default=0)) + 2
    img_w = max(get_display_width("图片数"), max((len(str(s.image_count)) for s in report.stats), default=0)) + 2
    box_w = max(get_display_width("框数"), max((len(str(s.box_count)) for s in report.stats), default=0)) + 2
    pct_w = max(get_display_width("图占比"), get_display_width("框占比"), 7) + 2     # 7 = "100.00%"
    status_w = max(get_display_width("状态"), max((get_display_width(s.status) for s in report.stats), default=0)) + 1
    widths = [name_w, img_w, box_w, pct_w, pct_w, status_w]
    aligns = ["left", "right", "right", "right", "right", "left"]

    out: List[Tuple[str, bool]] = []
    out.append(("数据平衡性报告".center(sum(widths) + len(widths) - 1, "="), False))
    out.append((format_table_row(["类别", "图片数", "框数", "图占比", "框占比", "状态"], widths, aligns), False))
    out.append((format_table_separator(widths), False))
    for s in report.stats:
        line = format_table_row(
            [s.name, str(s.image_count), str(s.box_count),
             f"{s.image_pct * 100:.2f}%", f"{s.box_pct * 100:.2f}%", s.status],
            widths, aligns,
        )
        out.append((line, s.name in flagged))          # 偏弱行标 True,调用方可高亮
    out.append((format_table_separator(widths), False))
    out.append((
        f"合计: {report.total_images} 张图, {report.total_boxes} 个框; "
        f"图数有用地板 ≈ {report.usefulness_img_floor} (低于它的类在 val/test 里多半摊不到样本)",
        False,
    ))

    # 有偏弱类才追加"建议"区。注意:这里只给建议,绝不替用户删类。
    if report.has_warnings:
        out.append(("", False))
        out.append((f"⚠️  以下类别偏弱: {', '.join(s.name for s in report.flagged)}", False))
        out.append(("   这只是提醒——本工具不会自动删类或改数据。处理方式:", False))
        if source_format in _CLASSES_FILTERABLE:
            keepers = report.keeper_classes()
            if keepers and len(keepers) < len(report.stats):
                kline = " ".join(f'"{k}"' for k in keepers)
                out.append((f"   · 想只训练正常的类, 重跑时加:  --classes {kline}", False))
            out.append(("   · 或者: 给偏弱的类补充/增强样本后重跑。", False))
        else:
            out.append(("   · yolo 源数据无法用 --classes 删类(会让 yaml 与 txt 的 id 对不上);", False))
            out.append(("     请在源头重写 txt 或补充样本。", False))
    return out
```

# 阶段 6:🧱 撞墙③ 覆盖率前置 + `raw/` 只读(中间产物走 tempfile)

## 6.1 🧱 撞墙③:残缺数据集会让你白跑半天

设想一个真实事故:某数据集 `images/` 有 1000 张图,但 `annotations/` 只导出了 100 个标注(中途断了 / 格式选错)。朴素流程会怎样?——它**照样跑完**:转换 100 个标注、配对、划分、写 yaml,一切"成功"。然后你高高兴兴开训,几小时后才发现 90% 的图根本没标注,模型废了。

问题在于:**残缺是在最后才暴露的,而它本可以在第一步就被发现。** 这就是 fail-fast 该上场的地方——开跑前先算一个**覆盖率**(有标注的图 / 总图),太低就当场终止:

```python
# 指挥家开跑前的"预检"之一(完整版见阶段 7 的 orchestrator._check_coverage):
n_images = sum(len(list(raw_images.glob(f"*{ext}"))) for ext in IMAGE_EXTENSIONS)
if annotation_format == AnnotationFormat.COCO:        # COCO 是单个 json,stem 级覆盖率不适用,跳过
    return
n_annos = len(list(raw_annotations.glob("*.*")))
coverage = n_annos / n_images
if coverage < COVERAGE_HARD_THRESHOLD:                # 0.5:低于直接终止
    raise ValueError(f"图像-标注覆盖率 {coverage:.1%} 低于硬阈值 {COVERAGE_HARD_THRESHOLD:.0%},终止以免训练废了……")
if coverage < COVERAGE_SOFT_THRESHOLD:                # 0.9:仅警告,可继续
    logger.warning("⚠️ 覆盖率 %.1f%% 偏低,建议核对。", coverage*100)
```

`constants.py` 再长出 `COVERAGE_HARD_THRESHOLD=0.5`、`COVERAGE_SOFT_THRESHOLD=0.9`。我们造一个"图多标注少"的残缺数据集,看这道闸是否拦得住(已验证,经 orchestrator 触发):

```text
✅ 拦下: 图像-标注覆盖率 10.0% 低于硬阈值 50%,终止以免训练废了(总图像 10, 有标注 1)。请检查 annotations/ 或确认 --format。
```

> 💡 **金句**:**"fail-fast 的价值,是把'几小时后才暴露的错',提前到'第一秒就报出来'。能在开跑前用一次 `glob` 算清楚的事,绝不拖到训练完。"**
> 📌 为什么 COCO 要跳过这个检查?因为 COCO 全数据集**一个 json**,不存在"每张图一个标注文件"的 stem 配对关系,按文件数算覆盖率没意义——所以按格式区别对待(这又是一次"接口一样、处理未必一样")。

## 6.2 `raw/` 是只读圣地:中间产物走 `tempfile`

转换会产出一堆中间 YOLO `txt`。它们该放哪?**绝不能放进 `data/raw/`**(回扣[公约二]、D0 决定 5:原始只读)。一旦往 `raw/` 写,你就污染了"唯一可信的原始数据",下次 `odp-reset` 还不敢删。

做法:转换的中间产物写进**系统临时目录**,用完即焚:

```python
import tempfile
from pathlib import Path
with tempfile.TemporaryDirectory(prefix="odp_pipe_") as tmp:   # 退出 with 自动清理
    staging = Path(tmp) / "labels"
    classes = convert_data_to_yolo(raw_annotations, staging, fmt, options)   # 中间 txt 落在 tmp
    pairs = pair_images_with_labels(staging)                                 # 配对后,真正要保留的才落 processed/
    ...
# 出了 with,tmp 整个被删 —— raw/ 自始至终没被碰过
```

> 💡 **金句**:**"区分'原始 / 中间 / 产物'三种数据:原始只读(raw)、中间用完即焚(tempfile)、产物可再生(processed)。中间产物借道 `tempfile`,既不脏 `raw`,也不在 `processed` 里留垃圾。"**

这两条纪律(覆盖率预检 + tempfile 中转)马上会成为指挥家的骨架。

# 阶段 7:指挥家 orchestrator + 引用解析 refs + `odp-transform` CLI

## 7.1 用户给的 `--dataset` 是"名字"还是"路径"?→ refs.py

`odp-transform --dataset safety_helmet` 里的 `safety_helmet` 是个**裸名字**(按约定去 `data/raw/` 找);但用户也可能写 `--dataset /data/external/foo` 这样的**绝对路径**。指挥家需要先把这种"名字或路径"统一解析成一个确定的目录。

这件事单独成一个小模块 `refs.py`。而且既然要写,就顺手**把验证 / 推理子系统将来要的解析也一起放好**——dataset 之外,还有 `yaml`(D4 验证要)、`pretrained_model` / `trained_model`(D5 训练 / 推理要)。它们判别规则完全一样,只是默认目录不同:

> 📄 **`apps/platform/src/od_platform/common/refs.py`** · 约 30 行
> **内容**:`resolve_ref(ref, *, base_dir, default_suffix)` 通用解析 + 四个语义化封装 `resolve_dataset` / `resolve_yaml` / `resolve_pretrained_model` / `resolve_trained_model`。
> **为什么这样设计**:**纯语法判别**——绝对路径、或带分隔符 → 当路径;否则当裸名字、按约定目录解析。故意**不掺 `path.exists()` 嗅探**:带点的名字(`my.dataset`)不会被误判成"有后缀的文件",规则可预测;想指当前目录的文件,就显式写 `./foo`。
> **现在为什么不做别的**:① 为什么今天 D3 只用到 `resolve_dataset`,却把 yaml/model 也写了?因为它们是**同一段逻辑的不同默认目录**,此刻一起放好是**零成本**,等 D4/D5 再回来加反而要重新理一遍上下文(回扣 D0 决定 3:"提前想清楚放哪,是几乎零成本的事")。这是"留接缝"而非"过度设计"——区别在于:接缝是同构逻辑的顺手扩展,过度设计是凭空造没用例的机制。② 为什么 `model` 解析有 `pretrained` / `trained` 两个?因为训练吃**预训练**权重、推理 / 验证吃**已训练**权重,默认目录不同,语义不该混。

```python
"""引用解析:把命令行给的 dataset / yaml / model "名字或路径",统一解析成确定的 Path。

为什么要它:
    用户可能写 --dataset safety_helmet(裸名字,按约定去 data/raw/ 找),也可能写
    --dataset /data/external/foo(绝对路径)。下游不该到处写"这是名字还是路径"的判断,
    集中到这里一次解析。

判别规则:【纯语法】,不嗅探磁盘。
    · 绝对路径,或带路径分隔符(parts > 1)→ 当成路径,原样 resolve。
    · 否则当裸名字 → 拼到约定目录下。
    故意不掺 path.exists() 来猜:这样规则可预测——带点的名字(my.dataset)不会被误判成
    "带后缀的文件";想指当前目录下的文件,显式写 ./foo 即可。

为什么今天(D3)就把 yaml / model 解析也写好(D0 决定 3:提前想清放哪是零成本):
    它们和 dataset 是【同一段逻辑、不同默认目录】。此刻顺手放好是零成本;等 D4 验证 /
    D5 训练再回来加,反而要重新理一遍上下文。这叫"留接缝",不是过度设计——区别在于:
    接缝是同构逻辑的顺手扩展,过度设计是凭空造没有用例的机制。
"""
from __future__ import annotations

from pathlib import Path
from typing import Optional

from od_platform.common.paths import (
    DATASET_CONFIGS_DIR,
    PRETRAINED_MODELS_DIR,
    RAW_DATA_DIR,
    TRAINED_MODELS_DIR,
)

def resolve_ref(ref: str, *, base_dir: Path, default_suffix: Optional[str] = None) -> Path:
    """通用解析:名字或路径 → Path。

    Args:
        ref: 用户给的字符串。
        base_dir: 当 ref 是裸名字时,拼接到哪个约定目录。
        default_suffix: 裸名字若没带这个后缀则补上(如 ".yaml"/".pt");路径形态不补。
    """
    p = Path(ref)
    if p.is_absolute() or len(p.parts) > 1:          # 绝对 / 带分隔符 → 当路径
        return p.resolve()
    name = ref if (not default_suffix or ref.endswith(default_suffix)) else ref + default_suffix
    return (base_dir / name).resolve()               # 裸名字 → 约定目录下

def resolve_dataset(ref: str) -> Path:
    """数据集:裸名字 → data/raw/<名字>/。← D3 今天就用它。"""
    return resolve_ref(ref, base_dir=RAW_DATA_DIR)

def resolve_yaml(ref: str) -> Path:
    """dataset yaml:给 D4 验证子系统的接缝(裸名字补 .yaml)。"""
    return resolve_ref(ref, base_dir=DATASET_CONFIGS_DIR, default_suffix=".yaml")

def resolve_pretrained_model(ref: str) -> Path:
    """预训练权重:给 D5 训练的接缝(训练吃 pretrained)。"""
    return resolve_ref(ref, base_dir=PRETRAINED_MODELS_DIR, default_suffix=".pt")

def resolve_trained_model(ref: str) -> Path:
    """已训练权重:给 D5/D4 推理/验证的接缝(推理吃 trained;与 pretrained 默认目录不同)。"""
    return resolve_ref(ref, base_dir=TRAINED_MODELS_DIR, default_suffix=".pt")
```

`paths.py` 此刻新增本课要的三个解析(按数据集分桶):`raw_dataset_root(name)`、`dataset_processed_dir(name) → data/processed/<name>/`、`dataset_yaml_path(name)`。

## 7.2 指挥家:把转换 → 报告 → 划分 → 落盘 → yaml 串成一条龙

现在所有零件齐了,用一个 `DatasetPipeline` 把它们按顺序串起来。**关键:指挥家自己不实现任何算法,它只编排;而且它不认识任何具体策略名**——对所有策略**统一**构建 `labels_per_image`,随机策略用不到就忽略、分层策略用得到就读。

> 📄 **`apps/platform/src/od_platform/data_pipeline/orchestrator.py`** · 约 75 行
> **内容**:`DatasetPipeline`——`__init__` 用 `resolve_dataset` 定位、按数据集算好落盘根 / yaml 路径;`run()` 依次:预检(含覆盖率)→ 取 converter + 校验 task → `tempfile` 里转换 → 配对(跨 `IMAGE_EXTENSIONS`)→ 构建 `labels_per_image` → 打报告 → 划分 → 落盘 → 写 yaml。
> **为什么这样设计**:① **依赖倒置**——它只调各模块的公开入口,不碰内部;换策略 / 加格式都不用改它。② **统一构建 labels** 让它对策略"无知",这是注册表"开闭"延伸到编排层。③ 配对走 `IMAGE_EXTENSIONS`(`constants` 第七段),所以 `.png/.jpeg/...` 都不会被漏(回避了"只认 `.jpg`"的坑)。
> **现在为什么不做别的**:为什么报告"只打不停"?因为"要不要因某类太少而中止"是**策略选择**,留给用户 / 上层,不写死在指挥家里(呼应"检查 ≠ 过滤")。

```python
"""端到端编排(指挥家):raw -> 转换(tempfile)-> 配对 -> 平衡报告 -> 划分 -> 落盘 -> 写 yaml。

指挥家的定位:它【只编排,不实现任何算法】,也【不认识任何具体策略名】——
    对所有策略统一构建 labels_per_image,由策略自取自用。所以换策略 / 加格式都不用改它。
    这是注册表的"开闭"一路延伸到编排层的体现。
"""
from __future__ import annotations

import logging
import tempfile
from pathlib import Path
from typing import Dict, List, Optional

from od_platform.common import paths
from od_platform.common.constants import (
    COVERAGE_HARD_THRESHOLD, COVERAGE_SOFT_THRESHOLD, DEFAULT_RANDOM_STATE,
    DEFAULT_SPLIT_STRATEGY, IMAGE_EXTENSIONS, AnnotationFormat, Task,
)
from od_platform.common.refs import resolve_dataset
from od_platform.data_pipeline.convert.registry import ConvertOptions, get_converter
from od_platform.data_pipeline.convert.service import convert_data_to_yolo
from od_platform.data_pipeline.report import analyze_class_balance, render_balance_report
from od_platform.data_pipeline.split.manifest import PairList
from od_platform.data_pipeline.split.materializer import SplitOutputDirs, materialize
from od_platform.data_pipeline.split.splitter import split_pairs
from od_platform.data_pipeline.split.yaml_writer import write_dataset_yaml

logger = logging.getLogger(__name__)

class DatasetPipeline:
    """一次"把某数据集转换 + 划分成可训练数据集"的完整流程。"""

    def __init__(
        self, dataset: str, annotation_format: str, *,
        task: str = Task.DETECT, train_rate: float = 0.8, val_rate: float = 0.1,
        classes: Optional[List[str]] = None, random_state: int = DEFAULT_RANDOM_STATE,
        split_strategy: str = DEFAULT_SPLIT_STRATEGY,
    ):
        self.annotation_format = annotation_format
        self.task = task
        self.train_rate = train_rate
        self.val_rate = val_rate
        self.random_state = random_state
        self.split_strategy = split_strategy
        self._options = ConvertOptions(task=task, classes=classes)

        # 名字或路径 → 具体目录;并据数据集名,提前算好"按数据集分桶"的落盘根与 yaml 路径。
        self.raw_root = resolve_dataset(dataset)
        self.dataset_name = self.raw_root.name
        self.raw_images = self.raw_root / "images"
        self.raw_annotations = self.raw_root / "annotations"
        self.processed_root = paths.dataset_processed_dir(self.dataset_name)   # data/processed/<name>/
        self.output_dirs = SplitOutputDirs.for_dataset_root(self.processed_root)
        self.yaml_out = paths.dataset_yaml_path(self.dataset_name)

    def run(self) -> Dict:
        logger.info("处理数据集 %r (format=%s, task=%s, split=%s)",
                    self.dataset_name, self.annotation_format, self.task, self.split_strategy)
        self._check_raw()                              # 预检(含覆盖率 fail-fast),不合格直接抛

        entry = get_converter(self.annotation_format)
        if not entry.supports(self.task):              # 格式不支持该 task,提前报清楚
            raise ValueError(f"格式 {self.annotation_format!r} 不支持 task={self.task!r}。支持: {entry.supported_tasks}")

        # ★ 转换的中间产物写进系统临时目录,出了 with 自动清理 —— 全程不碰 data/raw/(只读圣地)。
        with tempfile.TemporaryDirectory(prefix="odp_pipe_") as tmp:
            staging = Path(tmp) / "labels"
            classes = convert_data_to_yolo(self.raw_annotations, staging, self.annotation_format, self._options)
            pairs = self._pair_images_with_labels(staging)
            labels_per_image = self._build_labels_per_image(pairs, classes)

            # 划分前先打一份只读平衡报告(偏弱行用 WARNING 高亮)。它只提醒,不影响后续流程。
            report = analyze_class_balance(labels_per_image, classes, self.train_rate, self.val_rate)
            for line, is_warning in render_balance_report(report, self.annotation_format):
                (logger.warning if is_warning else logger.info)(line)

            manifest = split_pairs(
                pairs, train_rate=self.train_rate, val_rate=self.val_rate,
                random_state=self.random_state, strategy=self.split_strategy,
                labels_per_image=labels_per_image,     # 对所有策略统一传;随机会忽略它
            )
            counts = materialize(manifest, self.output_dirs)
            write_dataset_yaml(
                self.yaml_out, dataset_root=self.processed_root, classes=classes,
                manifest=manifest, dataset_name=self.dataset_name,
                source_format=self.annotation_format, task=self.task,
            )
        return {"counts": counts, "yaml": str(self.yaml_out)}

    # ---- 预检 ---------------------------------------------------------------
    def _check_raw(self) -> None:
        """开跑前的结构与覆盖率预检 —— 把"数据不对"挡在第一秒,而非训练后才发现。"""
        if not self.raw_root.is_dir():
            raise FileNotFoundError(f"数据集目录不存在: {self.raw_root}")
        if not self.raw_images.is_dir():
            raise FileNotFoundError(f"缺少 images 子目录: {self.raw_images}")
        if not self.raw_annotations.is_dir():
            raise FileNotFoundError(f"缺少 annotations 子目录: {self.raw_annotations}")
        self._check_coverage()

    def _check_coverage(self) -> None:
        """图像-标注覆盖率前置校验(撞墙③的解药)。"""
        n_images = sum(len(list(self.raw_images.glob(f"*{ext}"))) for ext in IMAGE_EXTENSIONS)
        if n_images == 0:
            raise FileNotFoundError(f"{self.raw_images} 下没有任何图像")
        if self.annotation_format == AnnotationFormat.COCO:
            # COCO 是单个 json,不存在"每图一标注文件"的 stem 配对,按文件数算覆盖率没意义 → 跳过。
            logger.debug("COCO 跳过 stem 覆盖率检查")
            return
        n_annos = len(list(self.raw_annotations.glob("*.*")))
        coverage = n_annos / n_images
        logger.info("覆盖率: %d/%d = %.1f%%", n_annos, n_images, coverage * 100)
        if coverage < COVERAGE_HARD_THRESHOLD:
            raise ValueError(
                f"图像-标注覆盖率 {coverage:.1%} 低于硬阈值 {COVERAGE_HARD_THRESHOLD:.0%},"
                f"终止以免训练废了(总图像 {n_images}, 有标注 {n_annos})。请检查 annotations/ 或确认 --format。"
            )
        if coverage < COVERAGE_SOFT_THRESHOLD:
            logger.warning("⚠️ 覆盖率 %.1f%% 低于软阈值 %.0f%%,可继续但建议核对。",
                           coverage * 100, COVERAGE_SOFT_THRESHOLD * 100)

    # ---- 配对 / 标签提取 ----------------------------------------------------
    def _pair_images_with_labels(self, labels_dir: Path) -> PairList:
        """把转换出的 txt 与原图按 stem 配对成 (图, 标) 列表。

        图像索引遍历 IMAGE_EXTENSIONS,所以 png/jpeg/... 都不会被漏(回避"只认 .jpg"的坑)。
        只保留"图存在"的标注;sorted 是复现前提。
        """
        image_index = {}
        for ext in IMAGE_EXTENSIONS:
            for img in self.raw_images.glob(f"*{ext}"):
                image_index[img.stem] = img
        pairs: PairList = []
        for lbl in sorted(labels_dir.glob("*.txt")):
            img = image_index.get(lbl.stem)
            if img is not None:
                pairs.append((img, lbl))
        return pairs

    def _build_labels_per_image(self, pairs: PairList, classes: List[str]) -> Dict[str, List[str]]:
        """从每个 txt 的首列 class_id 还原出"每张图有哪些类别名",供分层策略 / 报告用。"""
        result: Dict[str, List[str]] = {}
        for img_path, label_path in pairs:
            names: List[str] = []
            if label_path.exists():
                for line in label_path.read_text(encoding="utf-8").splitlines():
                    line = line.strip()
                    if line:
                        cls_id = int(line.split()[0])
                        if 0 <= cls_id < len(classes):
                            names.append(classes[cls_id])
            result[img_path.stem] = names
        return result
```

## 7.3 最后一层薄壳:`odp-transform` CLI

> 📄 **`apps/platform/src/od_platform/cli/transform_data.py`** · 约 30 行
> **内容**:`argparse` 解析参数 → 构造 `DatasetPipeline` → `run()` → 退出码(0 成功 / 1 数据错 / 2 用法错)。`--format` / `--task` / `--split-strategy` 的 `choices` 直接来自 `constants` 的 `all()`,**加了新格式 / 新策略,CLI 选项自动跟着多**(又一处不用改的地方)。
> **现在为什么不做别的**:为什么 CLI 这么薄?因为业务逻辑全在指挥家和各模块里;CLI 只负责"把命令行翻译成一次 `DatasetPipeline` 调用 + 给一个退出码"。薄壳才好测、好换(将来换成 Web API 也只是再写一层薄壳)。

```python
#!/usr/bin/env python
"""odp-transform CLI —— 原始数据集 → 可训练 YOLO 数据集。

CLI 极薄:只做三件事 —— 解析命令行参数、构造一个 DatasetPipeline、跑它并给一个退出码。
业务逻辑全在指挥家和各模块里;薄壳才好测、好换(将来换成 Web API 也只是再写一层薄壳)。
退出码约定:0=成功,1=数据/用法错误(被捕获),2=argparse 参数错误(argparse 自己用)。
"""
from __future__ import annotations

import argparse
import logging
import sys

from od_platform.common.constants import AnnotationFormat, SplitStrategy, Task
from od_platform.data_pipeline.orchestrator import DatasetPipeline

logger = logging.getLogger(__name__)

EXIT_OK = 0
EXIT_DATA_ERR = 1
EXIT_USAGE = 2

def main(argv=None) -> int:
    logging.basicConfig(level=logging.WARNING, format="%(message)s")
    p = argparse.ArgumentParser(
        prog="odp-transform",
        description="把 data/raw/<dataset> 转换 + 划分成可训练的 YOLO 数据集。",
    )
    p.add_argument("--dataset", required=True, help="数据集名 = data/raw/ 下的文件夹名(或一个路径)")
    # choices 直接用 constants 的 all():加了新格式/新策略,CLI 选项自动跟着多,无需改这里。
    p.add_argument("--format", required=True, choices=AnnotationFormat.all(), dest="fmt")
    p.add_argument("--task", default=Task.DETECT, choices=Task.all())
    p.add_argument("--split-strategy", default=SplitStrategy.RANDOM, choices=SplitStrategy.all(), dest="strategy")
    p.add_argument("--classes", nargs="+", default=None,
                   help="类别白名单(voc/coco: 过滤+重排; yolo: 仅命名,不能删类)")
    p.add_argument("--train-rate", type=float, default=0.8)
    p.add_argument("--val-rate", type=float, default=0.1)
    p.add_argument("--seed", type=int, default=42)
    a = p.parse_args(argv)

    pipe = DatasetPipeline(
        a.dataset, a.fmt, task=a.task, train_rate=a.train_rate, val_rate=a.val_rate,
        classes=a.classes, random_state=a.seed, split_strategy=a.strategy,
    )
    try:
        res = pipe.run()
    except (FileNotFoundError, ValueError) as e:       # 预期内的数据/用法错:友好提示 + 退出码 1
        logger.error("处理失败: %s", e)
        return EXIT_DATA_ERR
    print("✅ 完成:", res["counts"], "->", res["yaml"])
    return EXIT_OK

if __name__ == "__main__":
    sys.exit(main())
```

## 8.1 测试:七条,对应七个"我们已经验过的事实"

D0 把测试列为一等公民。我们不为覆盖率而写,而是把全篇**每一个 Checkpoint / 撞墙**钉成一条断言——以后谁改坏了,红灯立刻亮:

> 📄 **`apps/platform/tests/test_data_pipeline.py`** · 约 70 行 —— 七条:① 两张注册表都注册满;② 划分不丢图;③ 同种子可复现;④ 需要标签的策略没标签就 fail-fast;⑤ 分层把稀有类救回 val/test;⑥ 报告标记出稀有类;⑦ 残缺数据集被覆盖率前置拦截。

```python
"""data_pipeline 单元 + e2e 测试。把一路'当场验证'过的事钉成断言。"""
from pathlib import Path
import tempfile, pytest

from od_platform.data_pipeline.convert.service import convert_data_to_yolo
from od_platform.data_pipeline.convert.registry import ConvertOptions, list_capabilities
from od_platform.data_pipeline.split.splitter import split_pairs
from od_platform.data_pipeline.split.strategy_registry import list_strategies
from od_platform.data_pipeline.report import analyze_class_balance

RAW = Path("data/raw/demo")

def _pairs_and_labels():
    tmp = Path(tempfile.mkdtemp()) / "l"
    names = convert_data_to_yolo(RAW / "annotations", tmp, "pascal_voc", ConvertOptions(task="detect"))
    pairs, labels = [], {}
    for lbl in sorted(tmp.glob("*.txt")):
        img = RAW / "images" / (lbl.stem + ".jpg")
        pairs.append((img, lbl))
        ids = [int(x.split()[0]) for x in lbl.read_text().splitlines() if x.strip()]
        labels[lbl.stem] = [names[i] for i in ids]
    return pairs, labels, names

def test_registries_populated():
    assert set(list_capabilities()) == {"pascal_voc", "coco", "yolo"}
    assert set(list_strategies()) == {"random", "stratified", "stratified_multilabel"}

def test_split_loses_no_image():
    pairs, labels, _ = _pairs_and_labels()
    s = split_pairs(pairs, strategy="random").summary()
    assert s["train"] + s["val"] + s["test"] == s["total"] == len(pairs)

def test_random_reproducible():
    pairs, labels, _ = _pairs_and_labels()
    a = split_pairs(pairs, strategy="random", random_state=42).summary()
    b = split_pairs(pairs, strategy="random", random_state=42).summary()
    assert a == b

def test_stratified_requires_labels():
    pairs, _, _ = _pairs_and_labels()
    with pytest.raises(ValueError, match="labels_per_image"):
        split_pairs(pairs, strategy="stratified", labels_per_image=None)

def test_stratified_rescues_rare_class():
    pairs, labels, _ = _pairs_and_labels()
    m = split_pairs(pairs, strategy="stratified", labels_per_image=labels)
    rare_test = sum(1 for (im, _) in m.test if "反光衣" in labels[im.stem])
    rare_val = sum(1 for (im, _) in m.val if "反光衣" in labels[im.stem])
    assert rare_test + rare_val >= 1          # 分层把稀有类救回 val/test

def test_report_flags_rare_class():
```

## 8.2 ADR-003:把今天的关键决定记下来

> 📄 **`docs/adr/ADR-003-data-pipeline.md`**(节选)
>
> **状态**:已采纳 · **背景**:`data_pipeline` 要支持多标注格式 + 多划分策略,并保证产出可训练、可复现、可信。
>
> **决定**:
> 1. **格式与策略都用"注册表 + 自动注册"**,加新实现 = 加一个文件,框架(`registry`/`service`/`splitter`)不改。代价:多一层间接,读代码要绕一下——可接受,因实现数 ≥3 且会继续加。
> 2. **扫描逻辑(`import_submodules`)在第二张表出现时才抽进 `common/`**,不在第一张表就抽(避免过度设计)。
> 3. **检查 ≠ 过滤**:`report` 只读、只提醒,删类决定权留用户(走 `--classes`)。
> 4. **覆盖率前置 fail-fast**:残缺数据集开跑前终止,不让训练白干;COCO 因单 json 跳过 stem 级覆盖率。
> 5. **按数据集分桶** `data/processed/<name>/`:多数据集互不覆盖。
> 6. **多标签分层自研**,不引 `iterative-stratification`(算法仅 ~80 行;避开其 Python 版本隐患;且要"尽力分配不崩"而非 sklearn 的"<2 报错")。
> 7. **`raw/` 只读**,中间产物走 `tempfile`。
> 8. **`refs.py` 预置 yaml/model 解析接缝**,给 D4/D5 铺路(同构逻辑顺手扩展,非过度设计)。
>
> **被否决的替代**:工厂函数 / 抽象基类(加实现仍要改注册处或继承体系,不如装饰器 + 自动发现彻底);`sklearn` 分层(稀有类 <2 直接报错,不满足"不崩")。

## convert 与 split:同一个模子的两次浇筑

把两个子系统并排看,你会发现它们结构**严丝合缝地对称**——因为它们用的是同一套"注册表 + 自动注册"的解法:

| | convert(格式) | split(策略) |
|---|---|---|
| 一张表 | `registry._REGISTRY` | `strategy_registry._STRATEGY_REGISTRY` |
| 自登记 | `@register` | `@register_strategy` |
| 能力声明 | `supported_tasks` | `requires_labels` |
| 调度层(永不增长) | `service.convert_data_to_yolo` | `splitter.split_pairs` |
| 实现 = 加文件 | `converters/*.py` | `strategies/*.py` |
| 自动发现 | ←──── 共用 `common.registry_utils.import_submodules` ────→ | 同一行 |

> 这种对称不是刻意凑的,是同一个问题(多实现、可扩展)用同一把钥匙开锁的自然结果。你把 convert 这条路走通了,split 几乎是"换个名词重走一遍"——这正是概念手册说的"这条路你亲手走通一次,后面那几个一眼就认得"。

## 三堵墙,三个观念

| 撞墙 | 朴素做法的问题 | 解药 | 留下的观念 |
|---|---|---|---|
| ① 阶段 1–2 | `if/elif` 跨文件复制(漂移) | 注册表 + 自动注册 | 控制反转 / 开闭原则 |
| ② 阶段 4 | 纯随机把稀有类划进 0 张 | 分层 / 多标签(复用注册表) | 第二次才抽象 |
| ③ 阶段 6 | 残缺数据集白跑半天 | 覆盖率前置 fail-fast | 错误尽早暴露 |

## 🧭 这门课产出之后:D4 / D5 在等什么

今天交付的 `odp-transform`,产出物是 **`data/processed/<name>/` + `configs/datasets/<name>.yaml`**。它正是下游两门课的入口:

- **D4 · 验证子系统**:吃这份 yaml,做"标注合法性检查 + 抽样可视化"——而它的"检查项"又是一次注册表(`@check("名字")` 自己报到、调度层遍历表挨个执行),**和今天的格式 / 策略是同一个模子**。`refs.resolve_yaml` 今天已经给它备好了。
- **D5 · 训练子系统**:把 yaml 喂给 ultralytics 训练 / 评估;`odp_meta` 里的策略 / 种子 / 比例,让每次训练都说得清"数据是怎么来的"。`refs.resolve_pretrained_model` / `resolve_trained_model` 是它的接缝。

换句话说:**今天你不只建了一个转换工具,还把"注册表"这把钥匙、和给下游留的接缝,一起交到了 D4/D5 手里。**
