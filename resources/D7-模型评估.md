## 上一节回顾 + 本节挑战

**D6 给了我们什么。** 一个 `training` 子系统:`odp-train` 跑完一次训练,把 `best.pt` 归档进了 `models/trained/`,还在 `common/` 里留下一排跨任务工具(`result` / `config_log` / `plot_style` / `log_rename`),并立了三条接口承诺给 D7。

**但 D6 只到"训出来、存好"为止。** 一个训好的权重躺在 `models/trained/` 里,它到底准不准?这要靠**评估**——在数据集的验证集上跑一遍,算出 mAP、precision、recall。把评估这件事做成一个子系统,你会撞上几个问题:

1. **用户给"train3-best.pt"这个名字,怎么找到那个权重文件?** 它在 `models/trained/` 里,但用户给的是裸名字。谁来解析?
2. **评估和训练长得太像了,是不是该照搬训练的整套结构?** 训练有归档、有日志改名、有审计……评估要不要也来一套?哪些该抄,哪些不该?
3. **权重找不到怎么办?** 训练时找不到预训练权重可以去下载,评估呢?

这三个问题,第 1 个 D6 早替你留好了答案(只是朴素版没用),第 2 个是今天最该想清楚的判断,第 3 个藏着一个和训练**相反**的决定。照旧:先撞墙,再让结构长出来。

## 0.1 ValService 的边界:它比 TrainService 更"不发明"

评估子系统的核心是 `ValService`。它的边界和 `TrainService` 同款,而且**更克制**:

```
                 ┌────────────────────────────────────────┐
                 │   D7: ValService 编排器                │
                 │                                        │
                 │   它【不发明】(全走邻居):             │
                 │     · 配置合并 / 验证   → D5 build_val_config│
                 │     · 模型路径解析      → D3 refs.resolve_trained_model│
                 │     · logging handler   → D2(同 D6)        │
                 │     · 评估执行          → ultralytics model.val│
                 │     · 指标载体 / 配置视图 / 日志对齐 → D6 common│
                 │                                        │
                 │   它【只做】:                          │
                 │     · 把上面这些按评估顺序编排          │
                 │     · 评估前的 fail-fast 防御          │
                 │     · 写审计快照(kind=val)           │
                 │     · 兜住异常(永不抛)               │
```

## 0.2 盘家底:D7 凭什么几乎不写新 common 工具

这是 D7 最短、也最能说明问题的一节。D6 在 `common/` 留了一批工具,还在收尾时立了接口承诺。现在逐条取货:

| 评估时我需要…… | 直接复用 | 来自 |
|---|---|---|
| 合并验证过的评估配置 | `build_val_config(yaml, cli)` → `(config, merger)` | D5 |
| 把配置变 ultralytics 参数 | `config.to_ultralytics_kwargs()` | D5 |
| **把"权重名/路径"解析成已训练权重文件** | **`refs.resolve_trained_model(name)`** | **D3** |
| 数据集 yaml 解析 | `refs.resolve_yaml(name)` | D3 |
| **指标载体(和训练完全一样的字段)** | **`TrainMetrics`** → 起别名 `ValMetrics` | **D6** |
| 按字段打印配置 + 来源链 | `config_log.log_effective_config / log_override_chains` | D6 |

把这张表和 D6 的同款表对比一下:**D6 那张表后面还跟着"新建 4 个 common 工具";D7 这张表后面——什么都不跟。** D7 不往 `common/` 加任何东西。它要的能力,D6/D5/D4/D3/D2/D1 已经全给了。

### 模型解析:用 `resolve_trained_model`,且【不要】下载兜底

评估时用户写 `model: train3-best.pt`(裸名字),要解析成 `models/trained/train3-best.pt`。这一步用 D3 的另一个接缝——`resolve_trained_model`(D6 用的是 `resolve_pretrained_model`,D7 用 `resolve_trained_model`,各取各的):

```python
from od_platform.common.refs import resolve_trained_model

p = resolve_trained_model("train3-best.pt")        # → <项目>/models/trained/train3-best.pt
```

但和训练有个**关键的相反点**:训练时本地没有预训练权重,可以让 ultralytics 去下载(D6 的策略);**评估时本地没有"你训好的权重",就该当场失败**——你训练产出的权重,不存在"去网上下一个"的道理。所以评估侧**没有**那个 local-or-download 策略,取而代之的是 fail-fast(§4.2 细讲)。

🤔 **思考题(30 秒)**:同样是"解析权重路径",为什么训练用 `resolve_pretrained_model` 还带"下载兜底",评估用 `resolve_trained_model` 却要"找不到就失败"?

<!-- 讲师版 · 构建学员版时删除本块 ↓↓↓ -->
> 🎓 **思考题答案**:因为两种权重的"来历"不同。预训练权重(`yolo26n.pt`)是**公开的、可下载的**,本地没有去 hub 下一个天经地义;你训好的权重(`train3-best.pt`)是**你自己训练的私有产物**,世界上只有你的 `models/trained/` 里有它,"下载"无从谈起——找不到只能说明用户名字写错了或那次训练没归档,该立刻报错让他改,而不是默默去网上找一个不存在的东西。**同一个动作,兜底策略由'东西的来历'决定**——这正是 D3 当年坚持"两个场景两个解析器"的深层原因:它俩不只是目录不同,连"找不到该怎么办"都相反。

# 阶段 2:对外面板——ValResult + ValService

和 D6 一样,先定对外形状。你会发现它和 `TrainService` 高度同构——这正是 D6 把设计立对了的回报,但有几处**故意的不同**。

## 2.1 选型:编排器(跟 D6 同款,不重新论证)

`ValService` 也是编排器,不是 `model.val` 的包装器。理由 D6 §2.1 论证过,完全适用,这里不重复——**好设计的一个标志,就是下一个子系统能直接套用它的选型,不用从头再吵一遍。**

## 2.2 ValResult:跟 TrainResult 的两处差异

评估结果载体,大体照搬 `TrainResult`,但**少了归档相关的字段**——因为评估不产新模型(撞墙②会讲):

```python
# evaluation/service.py(节选)
from __future__ import annotations
from dataclasses import dataclass
from pathlib import Path
from typing import Optional


@dataclass(frozen=True)
class ValResult:
    """一次评估的结果事实(不可变载体)."""
    success: bool
    save_dir: Optional[Path]            # ultralytics 评估输出目录
    metrics: Optional["ValMetrics"]     # 评估指标(= TrainMetrics,见 §4.3)
    error: Optional[str] = None
    # ↑ 对比 TrainResult:没有 best_weight 字段 —— 评估不归档,没有"产出权重"这回事
```

🔗 **概念手册**:`ValResult` 是 frozen dataclass(手册①),和 `TrainResult` 同款设计——结果是事实,造好不可改。

⚠️ **设计点(`ValResult` 为什么没有 `best_weight`)**:`TrainResult` 有 `best_weight`(归档后的权重路径),`ValResult` 没有——因为**评估的产出是"一份指标报告",不是"一个新权重"**。字段的有无,诚实地反映了两个子系统产出的本质不同。别为了"和 TrainResult 长得一样"硬塞一个用不上的 `best_weight` 字段——那是虚假对称的第一步(下一阶段细讲)。

## 2.3 `ValService.evaluate()` 签名:比 `train()` 少一个开关

```python
class ValService:
    def evaluate(
        self,
        config_path: str,
        model: str,
        data: str,
        *,                              # keyword-only(同 D6)
        cli_overrides: Optional[dict] = None,
        rename_log: bool = True,        # 评估后是否对齐日志名
        # ↑ 注意:没有 archive 开关! 也没有 pre_validate(评估通常不重跑 D4 数据校验)
    ) -> ValResult:
        """编排一次评估,永不抛异常,结果包进 ValResult 返回."""
        ...
```

对比 `train()` 的三个开关(`pre_validate` / `archive` / `rename_log`),`evaluate()` 只剩 `rename_log` 一个。**少掉的两个开关,每一个都对应一个"评估和训练本质不同"的判断**——这不是偷懒,是想清楚后的精简。

## 2.4 `evaluate_yolo()` 便捷函数 + 这阶段不 commit

# 阶段 4:ValService 编排——含 D7 最重要的一堵墙

现在填内脏。大部分是把 D6/D5 的邻居按评估顺序串起来,但中间藏着 D7 真正要教的东西:**撞墙②——识别并拒绝"虚假对称"。**

## 4.1 模型解析 + fail-fast:找不到就失败,不下载

评估第一步,解析权重。用 D3 的 `resolve_trained_model`(纯解析),然后——和训练**相反**——加一道 **fail-fast**:

```python
from od_platform.common.refs import resolve_trained_model

weight = resolve_trained_model(model)               # 纯解析:→ models/trained/<name>.pt
if not weight.exists():                             # fail-fast:找不到就当场失败
    return ValResult(
        False, None, None,
        error=(f"找不到已训练权重:{weight}。"
               f"请确认名字正确、且该权重已被 D6 归档到 models/trained/。"),
    )
```

⚠️ **设计点(为什么评估是 fail-fast,训练是下载兜底)**:D6 训练时,`resolve_pretrained_model` 找不到权重会**交回裸名让 ultralytics 下载**——因为预训练权重是公开可下载的。D7 评估时,`resolve_trained_model` 找不到权重就**直接失败**——因为"你训好的权重"是私有产物,世界上只有你的 `models/trained/` 有它,下载无从谈起。**同一个'找权重'的动作,兜底策略相反**,而这个差异恰好落在 D3 早就拆好的两个解析器上(`pretrained` vs `trained`)。这是"两个场景两个解析器"在 D7 兑现的又一个证据。

## 4.2 🧱 撞墙②:对称强迫症——评估要不要也加 archive?

写到这,一个很强的冲动会冒出来:**"D6 的 TrainService 训练完会归档权重、改日志名、写审计……评估和训练长得这么像,是不是也该照搬一整套?archive 要不要也来一个?"**

先停下来想清楚"评估到底产出了什么":

```text
训练(D6)产出:  一个【新的权重文件】best.pt —— 是个要长期保留的【成品】
                 → 所以要 archive 到 models/trained/(把成品挑出来留好),合理。

评估(D7)产出:  一组【指标数字】mAP / precision / recall —— 是一份【报告】
                 → "归档一份报告"是什么意思?把指标复制到 models/trained/?
                    那里是放权重的,不是放报告的。评估【没有产出任何要归档的东西】。
```

**评估不归档。** 这不是"省事",是"评估和训练的产出本质不同":训练产出**成品**(要留存),评估产出**结论**(写进审计/日志即可)。强行给评估加一个 archive,你会发现自己**不知道该归档什么**——因为根本没有"评估产物"这种东西。

> **金句**:**"两个东西长得像,不代表它们该有一样的结构。识别'虚假对称'——看起来该对称、其实产出本质不同——是工程判断里最难、也最值钱的一种。评估不归档,因为它压根没有要归档的东西。"**

⚠️ **设计点(这堵墙为什么比 API 难)**:撞墙①②③(D6)和这里的撞墙②(D7)有个本质区别:前几堵是"某个东西不会用/顺序不对",照着修就行;**这一堵是'你以为该做的事,其实不该做'**——没有报错提示你,没有异常逼你,全靠你想清楚"评估的产出本质是什么"。新手会因为"对称好看"而照搬,老手会因为"产出不同"而拒绝。这种"拒绝虚假对称"的判断力,是这一篇最想留给你的东西。

<!-- 讲师版 · 构建学员版时删除本块 ↓↓↓ -->
> 🎓 **讲师笔记 · 4.2 ｜ 这是整个 D7 的最高潮,务必讲透**
> - 这堵墙的特殊在于:**它不会以任何报错的形式出现**。学员完全可以给评估硬加一个 archive,代码也能跑——只是那个 archive 不知道该存什么,最后要么存了个没意义的东西,要么是段死代码。"能跑但没意义"的设计错误,比"会崩"的错误更隐蔽、危害更长远。
> - 引导方式:别直接告诉他们"评估不归档",而是问"评估到底产出了什么?这个产出需要被长期保留吗?"让他们自己推出"指标是报告、不是成品、无需归档"。这个推导过程比结论重要。
> - 升华:虚假对称在工程里无处不在——"读接口有缓存,写接口是不是也该有""A 模块有重试,B 模块是不是也该有"。判据永远是**回到本质**:这两件事的"产出/语义"真的一样吗?一样才对称,不一样就别硬凑。这个判断力,值得反复强调。

## 4.3 复用指标载体:`ValMetrics = TrainMetrics`

评估的指标字段(task / fitness / mAP / precision / recall)和训练**完全一样**——因为 ultralytics 的 `DetMetrics` / `SegmentMetrics` 在训练和验证里是同一种对象。所以**不新建载体**,直接给 D6 的 `TrainMetrics` 起个语义化别名:

```python
# evaluation 里给一个语义化别名,让验证语境读起来更顺
from od_platform.common.result import TrainMetrics

ValMetrics = TrainMetrics              # 物理 SSoT 仍在 common.result,这里只是逻辑别名
```

⚠️ **设计点(为什么是"别名"而不是"新类")**:字段一模一样,新建一个 `ValMetrics` 类就是纯重复(两份会漂移)。但让验证代码 `from ...training import TrainMetrics` 又别扭(评估为什么要从训练拿东西)。**别名两全**:物理上是同一个类(零重复、零漂移),逻辑上有个贴合验证语境的名字。这和 D6 把 `TrainMetrics` 从 `common` 转再导出是同一种"物理一份、逻辑多名"的思路。

## 4.4 完整 `evaluation/service.py`

把零件串起来——你会看到它几乎全是调邻居,且**没有任何 archive**:

```python
#!/usr/bin/env python
# -*- coding:utf-8 -*-
# @FileName  : service.py
# @Project   : ODPlatform
# @Function  : ValService —— 编排 D5 配置 + D3 解析 + D2 日志 + ultralytics 评估(评估不归档)
"""评估编排器。不发明、不归档、不 import training;只编排、防御、审计、兜底。"""
from __future__ import annotations

import json
import logging
from dataclasses import dataclass
from datetime import datetime, timezone
from pathlib import Path
from typing import Optional

from od_platform.common.refs import resolve_trained_model, resolve_yaml         # D3 接缝
from od_platform.common.system_utils import log_device_info                     # D2
from od_platform.common.performance_utils import time_it                        # D2
from od_platform.common.config_log import log_effective_config, log_override_chains  # D6
from od_platform.common.result import TrainMetrics, log_train_metrics           # D6
from od_platform.common.log_rename import rename_log_to_save_dir                # D6
from od_platform.runtime_config import build_val_config                         # D5

logger = logging.getLogger(__name__)

ValMetrics = TrainMetrics              # 语义别名(物理 SSoT 在 common.result)


@dataclass(frozen=True)
class ValResult:
    success: bool
    save_dir: Optional[Path]
    metrics: Optional[ValMetrics]
    error: Optional[str] = None        # 注意:没有 best_weight —— 评估不产权重


class ValService:
    """评估编排器:不发明、不归档、永不抛异常."""

    def evaluate(
        self, config_path: str, model: str, data: str, *,
        cli_overrides: Optional[dict] = None, rename_log: bool = True,
    ) -> ValResult:
        try:
            return self._evaluate(config_path, model, data,
                                  cli_overrides=cli_overrides, rename_log=rename_log)
        except Exception as e:                          # 永不抛
            logger.error(f"评估失败:{e}", exc_info=True)
            return ValResult(False, None, None, error=str(e))

    def _evaluate(self, config_path, model, data, *, cli_overrides, rename_log) -> ValResult:
        # 1) 配置(走 D5 build_val_config)
        config, merger = build_val_config(config_path, cli_overrides or {})
        log_effective_config(config, merger, logger=logger)
        log_override_chains(config, merger, logger=logger)

        # 2) 模型解析 + fail-fast(走 D3 refs.resolve_trained_model,找不到就失败,不下载)
        weight = resolve_trained_model(model)
        if not weight.exists():
            return ValResult(False, None, None,
                error=f"找不到已训练权重:{weight}。请确认名字正确、且已被 D6 归档到 models/trained/。")

        # 3) 数据集 yaml(走 D3 refs,和 D4/D6 同一个)
        data_yaml = resolve_yaml(data)

        # 4) 环境快照(走 D2)
        log_device_info(logger=logger)

        # 5) 评估(@time_it 计时)
        results = self._run_eval(str(weight), config, data_yaml)

        # 6) 提取产物:save_dir(版本兜底)+ 指标
        save_dir = self._extract_save_dir(results)
        metrics = self._extract_metrics(results, config.task)
        log_train_metrics(metrics, logger=logger)       # 复用 D6 的指标打印

        # 7) 训练后整理:只对齐日志名 —— 【没有 archive】(撞墙②)
        if rename_log and save_dir is not None:
            rename_log_to_save_dir(save_dir, weight.stem)

        # 8) 审计(kind=val,区别于 train)
        self._write_audit(save_dir, config, metrics)

        return ValResult(True, save_dir, metrics)

    @staticmethod
    @time_it
    def _run_eval(weight: str, config, data_yaml):
        from ultralytics import YOLO
        model = YOLO(weight)
        return model.val(data=str(data_yaml), **config.to_ultralytics_kwargs())

    @staticmethod
    def _extract_save_dir(results) -> Optional[Path]:
        """ultralytics 不同版本 save_dir 位置不一,做兜底."""
        sd = getattr(results, "save_dir", None)
        if sd is None:
            sd = getattr(getattr(results, "speed", None), "save_dir", None)
        return Path(sd) if sd else None

    @staticmethod
    def _extract_metrics(results, task: str) -> ValMetrics:
        box = getattr(results, "box", None)
        rd = getattr(results, "results_dict", {}) or {}
        g = lambda a, k: float(getattr(box, a, None) or rd.get(k, 0.0)) if box else float(rd.get(k, 0.0))
        return ValMetrics(
            task=task,
            fitness=float(getattr(results, "fitness", 0.0) or rd.get("fitness", 0.0)),
            map50=g("map50", "metrics/mAP50(B)"),
            map50_95=g("map", "metrics/mAP50-95(B)"),
            precision=g("mp", "metrics/precision(B)"),
            recall=g("mr", "metrics/recall(B)"),
        )

    @staticmethod
    def _write_audit(save_dir, config, metrics) -> None:
        audit = {
            "kind": "val",                              # ← 区别于 train 的审计
            "utc": datetime.now(timezone.utc).isoformat(),
            "config": config.to_audit_snapshot(),       # D5 脱敏快照
            "metrics": {
                "fitness": metrics.fitness, "map50": metrics.map50,
                "map50_95": metrics.map50_95, "precision": metrics.precision, "recall": metrics.recall,
            },
            "save_dir": str(save_dir) if save_dir else None,
        }
        if save_dir:
            out = Path(save_dir) / "odp_audit.json"
            out.write_text(json.dumps(audit, ensure_ascii=False, indent=2), encoding="utf-8")
            logger.info(f"审计快照已写入:{out}")


def evaluate_yolo(
    config_path: str, model: str, data: str, *,
    cli_overrides: Optional[dict] = None, rename_log: bool = True,
) -> ValResult:
    """便捷函数:内部就是 ValService().evaluate(...),不重复逻辑."""
    return ValService().evaluate(
        config_path, model, data, cli_overrides=cli_overrides, rename_log=rename_log,
    )
```

数一眼 `_evaluate` 的步骤注释:配置→D5、解析→D3、环境→D2、评估→ultralytics、指标打印→D6。和 `TrainService` 一样,自己写的只有"顺序 + fail-fast + 审计 + 兜底"。而且——**通篇没有一个 `archive`**。

🔗 **概念手册**:`build_val_config` 返回 Pydantic 模型,`to_ultralytics_kwargs` / `to_audit_snapshot` 是其方法(手册④);`ValMetrics`/`ValResult` 是 dataclass(手册①)。

## 一次撞墙,回看

## D7 给 D8(推理)的接口承诺

D8(inference 子系统)接手时,能继续享受这套约定:

- **找权重**:推理用的也是"你训好的权重",同样走 `refs.resolve_trained_model` 从 `models/trained/` 找——和 D7 一模一样,且同样 fail-fast(私有权重不下载)。
- **复用工具**:`config_log` / `log_rename` / `plot_style` / `result` 全在 `common/`,D8 直接 import。
- **边界契约**:`inference/` 同样不 import `training/` 或 `evaluation/`(单向依赖)。
