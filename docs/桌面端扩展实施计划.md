# ODPlatform 桌面端扩展实施计划

> 最后更新: 2026-07-09

## Context

ODPlatform 是一个基于 YOLO 的目标检测开发平台（教学项目），核心引擎已完成 D0-D8 及 frame_source 讲义所描述的功能。`resources/项目扩展项.md` 列出了待完成的扩展项，其中**桌面端（PySide6）**是"其他扩展点1"中需完成的任务。

## 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| GUI 框架 | **PySide6** (>=6.6.0) | LGPL 许可证、Qt 官方维护、Qt 6 对齐 |
| 窗口模式 | **单窗口 QTabWidget** | 6 个页面是互斥工作流，无需 MDI 复杂度 |
| 长任务处理 | **QThread + 信号/槽** | 符合 D0 单进程约束，UI 保持响应 |
| 推理预览 | **自定义 QtSignalSink** | 复用引擎 `OutputSink` 抽象，零拷贝帧传递 |
| 训练进度 | **日志解析** | log handler 实时解析 epoch/loss |
| 配置编辑 | **表单 + YAML 双模式** | 利用 Pydantic 字段元数据自动生成表单，同时保留原始 YAML 编辑 |

## 数据流架构

```
UI 线程 (Qt Event Loop)
  │
  ├── Page Widget ──(启动)──> Worker Thread ──(调用)──> od_platform 服务层
  │                                                         │
  │                              ┌─ 日志 ──> QtLogHandler ──┤
  │                              │                          │
  └── LogViewer <──(信号)────────┘                          │
  └── ProgressPanel <──(信号)──── 进度事件                   │
  └── FrameViewer <──(信号)────── 帧数据 (推理)              │
  └── CheckResultsTable <──(信号)─ 质检结果                  │
```

### 推理帧管线

```
渲染线程 ──> QtSignalSink.write(frame, annotated)
                  │
                  v   (跨线程信号, QueuedConnection)
           FrameViewer.on_frame(annotated)
                  │
                  v
           BGR ndarray -> QImage -> QPixmap -> label.setPixmap()
```

| 桌面功能 | 复用的引擎模块 |

| 日志 | `od_platform.common.logging_utils` |

## 实施阶段 (完成状态)

### Phase 1: 骨架 + 项目页面 ✅
- pyproject.toml、app.py、main_window.py
- 6 个 Tab 占位，Project 页面完整实现
- QtLogHandler 桥接引擎日志到 LogViewer
- 状态栏显示工作区路径 + GPU 信息
- 深色主题 (VS Code 风格)

### Phase 2: 数据流水线页面 ✅
- 数据集选择器 (扫描 data/raw/)
- 格式/任务/划分配置 (resplit/preserve + 策略选择)
- PipelineWorker 封装 `DatasetPipeline.run()`
- 进度条 + 成功/失败结果展示

### Phase 3: 数据质检页面 ✅
- 数据集选择器 (扫描 configs/datasets/*.yaml)
- ValidationWorker 封装 `validate_dataset()`
- CheckResultsTable: 检查项 / 严重级别(颜色编码) / 摘要
- 点击行展开 JSON 详情
- 严重级别汇总栏 (PASS/INFO/WARNING/ERROR 计数)

### Phase 4: 配置编辑器页面 ✅
- 配置类型选择 (train/val/infer, 从 CONFIG_REGISTRY)
- 文件选择器 (扫描 configs/runtime/*.yaml)
- ConfigForm: 从 Pydantic 字段元数据自动生成表单控件
  - bool→QCheckBox, int→QSpinBox, float→QDoubleSpinBox
  - str→QLineEdit, list→逗号分隔, Optional→启用复选框
  - Union[bool,str]→QComboBox
- YamlEditor: QSyntaxHighlighter 6 色语法高亮
- 双模式 Form ↔ YAML 双向同步
- 生成默认 / 保存 / 重新加载

### Phase 5: 训练页面 ✅
- 模型选择器 (扫描 models/pretrained/ + models/trained/)
- 数据集选择器 (扫描 configs/datasets/*.yaml)
- 训练参数: Epochs / Imgsz / Batch / Device
- TrainingWorker: 自定义 LogHandler 正则解析 epoch/loss
- 实时指标: Epoch 进度 / Box/Cls/DFL Loss
- 停止按钮 (terminate worker)

### Phase 6: 推理页面 ✅
- 源选择: 摄像头/视频文件/图片文件/图片文件夹
- 浏览按钮: QFileDialog
- 推理参数: 置信度 / IoU阈值 / 图像尺寸
- QtSignalSink: OutputSink 协议 → Qt 信号
- FrameViewer: QLabel + QTimer(33ms≈30FPS) 实时显示
- 实时统计: FPS / 帧数 / 检测数 / 耗时
- 控制: 开始 / 停止(CancelToken) / 截图当前帧

### Phase 7: 打磨集成 ⬜
- 配置编辑器表单字段类型覆盖优化
- 错误处理和空状态提示完善
- About 对话框已有
- QSettings 持久化已有 (窗口几何 + 最后 Tab)
- 键盘快捷键已有 (Ctrl+1~6, Ctrl+Q)

## 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| 训练进度解析不稳定 | log handler 正则匹配 Ultralytics epoch 输出 |
| 推理帧转换性能 | FrameViewer 定时器限帧 30FPS, QPixmap 缩放 |
| 70+ 配置字段表单性能 | QScrollArea, QGroupBox 分组, 按需创建 |
| 线程安全 | 严格遵守"不跨线程调 GUI", 全部通过信号/槽 |
| 引擎依赖 | `pip install -e apps/platform` 确保 od_platform 可导入 |
| QObject/ABC 元类冲突 | QtSignalSink 实现协议不继承 OutputSink (duck typing) |
