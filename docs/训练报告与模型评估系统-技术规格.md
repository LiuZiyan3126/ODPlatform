# 训练报告与模型评估系统 — 技术规格

## 需求确认汇总

### 训练报告（D6 扩展）

| 维度 | 决策 |
|------|------|
| 输出格式 | **Markdown 文件** |
| 身份标识 | **`--author` CLI 参数** |
| 数据质量 | **可选引用**（不强制验证，在报告中注明数据集路径和版本） |
| 存储方式 | **纯文件系统** |

报告需覆盖的要素：**谁 → 什么时间 → 哪份数据 → 数据质量 → 训练了什么 → 结果如何**

### 模型评估（D7 新建）

| 维度 | 决策 |
|------|------|
| 评估内容 | **全套**：基础指标 + 逐类分解 + 可视化 + 审计快照 |
| 多模型对比 | **MVP：同数据集不同模型**，后续扩展交叉评估 |
| 触发方式 | **独立 CLI + 训练后自动触发** |
| 对比报告 | **终端 + Markdown 文件** |

## 一、训练报告 — 要实现什么

**一句话目标**：在 `TrainService.train()` 完成后，自动生成一份 Markdown 训练报告。

**报告模板**：

```markdown
# 训练报告 — {experiment_name}

## 基本信息
| 字段 | 值 |
|------|-----|
| 训练人 | {--author 的值} |
| 训练时间 | {开始时间} ~ {结束时间}，总耗时 {X 分 Y 秒} |
| 机器 | {CPU型号} / {GPU型号} / {CUDA版本} |

## 数据集
- 数据集名称：{--data 的值}
- 数据集路径：{解析后的 YAML 路径}
- 数据质量报告：{如果有 → 链接到 runs/data_validation/xxx/report.json；如果无 → 标注"未验证"}

## 训练配置
（以表格列出关键超参：model, epochs, batch, imgsz, optimizer, lr0, device, amp 等）
完整配置见：{od_audit.json 路径}

## 训练结果
| 指标 | 值 |
|------|-----|
| mAP@50 | ... |
| mAP@50-95 | ... |
| Precision | ... |
| Recall | ... |
| 训练速度 | ... |
```

**集成点**：修改 `training/service.py` 的 `TrainService.train()` 方法，在 `archive_checkpoints()` 之后、返回 `TrainResult` 之前插入报告生成步骤。

**新增文件**：
- `training/report.py` — `generate_train_report()` 函数，接收 `TrainResult` + `author: str` + `data_quality_report_path: Optional[str]`，写入 Markdown

**CLI 变更**：`cli/model_train.py` 加 `--author` 参数（可选，默认空字符串），传给 `TrainService`。

## 二、模型评估 — 要实现什么

**一句话目标**：新建 `odp-eval` CLI 命令 + `ValService`，在 test 数据上评估模型并生成报告。

**ValService 流程**：

1. 调用 `build_val_config()` 加载评估配置
2. 解析模型权重路径（`resolve_model_path`，从 `models/trained/` 里选）
3. 解析数据集路径（`resolve_dataset_path`）
4. 调用 YOLO `model.val()` 获取结果
5. 提取指标（复用 `TrainMetrics` 的提取逻辑）
6. 将 ultralytics 生成的可视化产物（PR 曲线、混淆矩阵等）复制到评估输出目录
7. 生成 Markdown 评估报告
8. 写入审计快照

**新增文件**（建议结构）：

```
od_platform/
├── evaluation/              # 新包
│   ├── __init__.py
│   ├── service.py           # ValService — 评估编排
│   ├── report.py            # generate_eval_report() — Markdown 报告生成
│   └── compare.py           # compare_models() — 多模型对比
├── cli/
│   ├── model_eval.py        # odp-eval CLI 入口
│   └── model_compare.py     # odp-compare CLI 入口
```

**CLI 接口设计**：

```bash
# 单模型评估
odp-eval \
  --model fire_v1_yolo11n-best.pt \     # 模型权重（从 models/trained/ 选）
  --data fire.yaml \                    # 数据集
  --yaml val.yaml \                     # 评估配置 YAML
  --author "张三" \                     # 评估人
  --split test                          # 在 test 分片上评估

# 多模型对比
odp-compare \
  --models fire_v1_yolo11n-best.pt fire_v2_yolo11s-best.pt \
  --data fire.yaml \
  --split test \
  --author "张三"
```

## 三、多模型对比 — MVP 范围

**只做"同数据集不同模型"**。

**终端输出**（带颜色）：

```

┌─────────────────────────┬──────────┬──────────┬───────────┬──────────┐
│ Model                   │ mAP@50   │ mAP@50-95│ Precision │ Recall   │
├─────────────────────────┼──────────┼──────────┼───────────┼──────────┤
│ fire_v1_yolo11n-best    │ 0.8523   │ 0.6234   │ 0.8912    │ 0.7845   │
│ fire_v2_yolo11s-best    │ 0.8710 ▲ │ 0.6512 ▲ │ 0.9021 ▲  │ 0.8012 ▲ │
```

**Markdown 报告**：同样的对比表格 + 逐类指标对比子表 + 结论摘要。

## 四、关键集成注意点

1. **训练后自动评估**：如果在 CLI 中指定 `--auto-eval`，在 `TrainService.train()` 最后、报告生成之后，调用 `ValService.evaluate()` 评估刚训练好的 best.pt，然后把评估结果追加到训练报告里。
2. **报告文件位置**：
   - 训练报告：`runs/train/{experiment_name}-{timestamp}/report.md`
   - 评估报告：`runs/eval/{model_stem}-{timestamp}/report.md`
   - 对比报告：`runs/compare/{timestamp}/report.md`
3. **不要引入数据库**，一切以文件系统为准，但数据结构设计时留好接口（比如所有指标都用 dataclass + `to_dict()`）。
4. **复用不要重复造轮子**：`TrainMetrics`、`build_val_config()`、`resolve_model_path`、`resolve_dataset_path`、`log_effective_config` 都是现成的，直接引用。

## 五、验收标准

| 功能 | 验收条件 |
|------|----------|
| 训练报告 | `odp-train ... --author "张三"` 完成后，`runs/train/<run_id>/` 下出现 `report.md`，包含全部 5 要素（谁、什么时间、哪份数据、数据质量、结果） |
| 单模型评估 | `odp-eval --model xxx.pt --data fire.yaml --split test` 输出评估指标 + 生成 `runs/eval/<id>/report.md` |
| 训练后自动评估 | `odp-train ... --auto-eval` 训练完成后自动跑 test 评估，结果进报告 |
| 多模型对比 | `odp-compare --models a.pt b.pt --data fire.yaml` 终端输出对比表格 + 生成 Markdown |
| 可视化 | 评估输出目录包含混淆矩阵、PR 曲线等图表（ultralytics 自动生成，只需复制留存） |
