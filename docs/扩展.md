## 1. split_mode 是否划分 扩展
本次扩展为数据集转换流程新增了“保留原有数据划分”的能力，目标是兼容 Roboflow 等已经按 `train/valid/test` 划分好的数据集，避免在转换格式时重新随机划分，从而保留原始数据隔离关系和评估语义。原有流程保持不变，仍然是默认的 `resplit` 模式，即读取 `data/raw/<dataset>/images` 和 `data/raw/<dataset>/annotations`，先统一转换为 YOLO 标签，再通过已有 split strategy 重新划分为 `train/val/test`。新增的 `preserve` 模式则读取 `data/raw/<dataset>/train`、`valid|val|validation`、`test` 目录，分别对每个 split 内的标注进行格式转换，并直接构造 `SplitManifest(train, val, test)`，最后复用现有的 `materialize()` 和 `write_dataset_yaml()` 输出到标准的 `data/processed/<dataset>/train|val|test` 结构。

代码层面，在 `common/constants.py` 中新增了 `SplitMode` 常量类，定义 `RESPLIT = "resplit"` 和 `PRESERVE = "preserve"`，并增加 `DEFAULT_SPLIT_MODE = SplitMode.RESPLIT`，保证旧命令默认行为不变。在 `cli/transform_data.py` 中新增了 `--split-mode {resplit,preserve}` 参数，其中 `resplit` 表示转换后重新划分，`preserve` 表示保留已有划分，只做格式转换。在 `data_pipeline/orchestrator.py` 中，`DatasetPipeline.run()` 被拆分为两条流程：`_run_resplit()` 承载原有逻辑，`_run_preserve_split()` 承载新增逻辑；同时新增了 split 目录发现、preserve 模式预检、类别解析和指定图片目录配对等辅助方法。

新增 preserve 流程支持将常见目录名标准化：`train` 映射为平台的 `train`，`val`、`valid`、`validation` 映射为平台的 `val`，`test` 映射为平台的 `test`。其中 `train` 和 `val` 是必要划分，`test` 可被识别并保留。对于 Pascal VOC 和 COCO，如果用户未显式传入 `--classes`，系统会从所有 split 的标注中扫描类别并生成统一类别表；对于 YOLO 格式，由于标签文件只包含数字类别 id，不包含类别名，因此在 `preserve + yolo` 模式下必须显式提供 `--classes`，以保证生成的 dataset yaml 中 `names` 与标签 id 对齐。

本次设计没有新增 split mode 注册表，因为当前 split mode 只有两类大流程：未划分数据重新划分，以及已划分数据保留结构。它们更像 pipeline 层面的流程分支，而不是普通的 split strategy。现有 `strategy_registry.py` 继续只负责 `resplit` 模式下“如何划分一批样本”，例如 random、stratified 等策略；新增的 `preserve` 模式则绕过重新划分策略，直接从已有目录结构构造 `SplitManifest`。这样能保持架构语义清晰：`split_mode` 决定是否保留已有划分，`split_strategy` 只决定重新划分时采用什么策略。

典型使用方式如下：

```powershell
odp-transform --dataset fire --format pascal_voc --task detect --split-mode preserve --classes fire hunman-fire
```

该命令会读取：

```text
data/raw/fire/train
data/raw/fire/valid
data/raw/fire/test
```

并输出为平台标准结构：

```text
data/processed/fire/train/images
data/processed/fire/train/labels
data/processed/fire/val/images
data/processed/fire/val/labels
data/processed/fire/test/images
data/processed/fire/test/labels
```

同时生成：

```text
apps/platform/configs/datasets/fire.yaml
```

验证方面，已完成 Python 编译检查，`odp-transform --help` 能正常显示新增的 `--split-mode` 参数，并对 `fire` 数据集进行了只读预检，系统能够识别 `train -> train`、`valid -> val`、`test -> test`，并发现类别 `hunman-fire` 和 `fire`。
