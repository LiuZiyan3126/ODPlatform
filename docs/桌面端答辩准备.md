# ODPlatform 桌面端答辩准备

## 一、架构设计类

### Q1: 为什么用 PySide6 而不是 PyQt5？

- **官方维护**: PySide6 是 Qt 公司的官方 Python 绑定，PyQt5 是第三方 (Riverbank Computing)
- **许可证**: PySide6 使用 LGPL，更宽松；PyQt5 使用 GPL，闭源分发需商业许可
- **版本对齐**: PySide6 基于 Qt 6（当前版本），PyQt5 基于 Qt 5（2023 年已停止支持）
- **社区趋势**: 新项目基本都选 PySide6，Qt 官方文档的 Python 示例用 PySide6

### Q2: 桌面端和引擎之间怎么通信的？通过 subprocess 调用 CLI 吗？

**不通过 subprocess**。桌面端直接 `import od_platform` 调用服务层：

```
桌面端 Page → Worker(QThread) → od_platform 服务层函数
```

复用的关键函数：

| 桌面功能 | 直接调用的引擎函数 |
|----------|-------------------|
| 项目初始化 | `od_platform.cli.init_project.initialize_project()` |
| 项目重置 | `od_platform.cli.reset_project.reset_project()` |
| 数据流水线 | `DatasetPipeline(...).run()` |
| 数据质检 | `validate_dataset(yaml_path=...)` |
| 模型训练 | `train_yolo(cli_args=...)` |
| 模型推理 | `infer_yolo(cli_args=..., output_sink=..., hooks=..., cancel_token=...)` |

**好处**:
- 零序列化开销，直接传 Python 对象
- 可以复用引擎提供的 `InferHooks`/`OutputSink`/`CancelToken` 三个接缝
- 所有引擎日志自动冒泡到桌面端的日志查看器

**代价**: 耦合在同一进程，引擎崩溃桌面端也会挂。

### Q3: 为什么用 QThread 而不是 multiprocessing？

| | QThread | multiprocessing |
|---|---|---|
| 数据传递 | 信号/槽，零拷贝传 Python 对象 | pickle 序列化，大对象（ndarray）慢 |
| 取消机制 | `CancelToken`（threading.Event） | 需要 IPC（信号/共享内存） |
| 框架复杂度 | Qt 原生支持 | 需要额外处理进程生命周期 |
| 符合 D0 约束 | 单进程设计 | 破坏单进程约定 |

D0 设计指南约定单进程串行设计，QThread 只用于保持 UI 响应。引擎内部的 `ThreadedPipeline` 已经做了多线程流水线（Reader → 推理 → Renderer → Display）。

### Q4: 6 个 Tab 之间有没有数据依赖？

```
数据流水线 → 数据质检 → 模型训练 → 模型推理
    │                        │
    └── 生成 YAML ──────────→┘ (训练和推理都需要数据集配置)
```

- 逻辑上有顺序依赖，但不强制——各 Tab 独立，跳步也能工作
- 数据集 YAML（`configs/datasets/<name>.yaml`）是流水线的输出、质检/训练的输入
- 训练产物（`models/trained/`）是推理的输入

## 二、Qt/PySide6 细节类

### Q5: QPlainTextEdit 的日志颜色是怎么实现的？

**踩坑记录**: `QPlainTextEdit.setTextColor()` 在 PySide6 上**不存在**（这是旧版 Qt C++ 的 API，PySide6 没有包装）。

**正确实现**:

```python
# ❌ 错误: PySide6 没有这个方法
self._text.setTextColor(color)
self._text.insertPlainText(message + "\n")

# ✅ 正确: QTextCharFormat + setCurrentCharFormat
fmt = QTextCharFormat()
fmt.setForeground(color)
self._text.setCurrentCharFormat(fmt)
self._text.appendPlainText(message)
```

**完整流程**:
1. 自定义 `QtLogHandler(logging.Handler)` → `emit()` 方法里发射 Qt 信号
2. signal 带 `(message, levelno)` 两个参数
3. `LogViewer._on_log` slot 根据 level 查颜色表，创建 `QTextCharFormat`，调用 `appendPlainText`
4. 用 `QueuedConnection` 确保 slot 在 UI 线程执行

### Q6: Signal/Slot 跨线程怎么保证安全？

两条规则：

1. **所有跨线程信号用 `QueuedConnection`**: slot 在接收者所在线程执行，不阻塞发送者
2. **帧数据 emit 前 `.copy()`**: 渲染线程和 UI 线程不共享同一块 ndarray 内存

```python
# QtSignalSink.write() 在 _Renderer 线程调用
def write(self, frame, annotated):
    self.frame_ready.emit(annotated.copy())  # copy!

# InferencePage 连接时明确指定 QueuedConnection
self._worker.frame_ready.connect(
    self._viewer.on_frame, Qt.QueuedConnection,
)
```

### Q7: 推理帧预览为什么不是每帧刷新而是 30FPS？

- `FrameViewer` 用 `QTimer(33ms)` 定时拉取最新帧（约 30FPS）
- 引擎可能跑到 60-90 FPS，但每帧都做 `BGR→RGB→QImage→QPixmap` 转换 UI 会卡
- 人眼超过 30FPS 感知差异不大
- 缩放时用 `Qt.SmoothTransformation` 按比例缩放，进一步降低开销

```python
self._timer = QTimer(self)
self._timer.timeout.connect(self._update_display)
self._timer.start(33)  # ~30 FPS
```

### Q8: 日志查看器为什么不直接用 QTextEdit 追加？

`QPlainTextEdit` 更适合大文本：
- 不存储富文本格式信息，内存占用小
- `setMaximumBlockCount(5000)` 自动清理旧行
- `appendPlainText` 比 `QTextEdit.append` 快

## 三、引擎集成类

### Q9: QtSignalSink 为什么没继承 OutputSink ABC？

**元类冲突**:
```python
# ❌ 这样会报错:
class QtSignalSink(QObject, OutputSink):
    ...
# TypeError: metaclass conflict:
#   QObjectMeta vs ABCMeta — 不相容的元类

# ✅ 解决方案: duck typing
class QtSignalSink(QObject):  # 只继承 QObject
    def open(self, output_dir, source_type): ...
    def write(self, frame, annotated): ...
    def close(self): ...
```

Python 鸭子类型允许不继承抽象基类，只要实现了同名方法就能传进去。Python 中 `OutputSink` 作为类型注解时引擎不做运行时 isinstance 检查。

### Q10: 训练进度是怎么获取的？

**自定义 logging.Handler 解析 Ultralytics 训练日志**:

```python
_EPOCH_PATTERN = re.compile(r"^\s*(\d+)/(\d+)\s+")
_LOSS_PATTERN = re.compile(
    r"^\s*\d+/\d+\s+[\d.]+\w*\s+([\d.]+)\s+([\d.]+)\s+([\d.]+)"
)
```

匹配 Ultralytics 输出行:
```
  1/100    3.12G    0.8324    0.4562    0.9123    ...
  ↑         ↑        ↑         ↑         ↑
epoch/total  GPU    box_loss  cls_loss  dfl_loss
```

`TrainingWorker.run()` 开始时安装 handler → 解析日志行 → emit `progress` 和 `metrics_update` 信号 → 训练结束移除 handler。

### Q11: CancelToken 怎么工作的？点了停止后多久会停？

```python
class CancelToken:
    def __init__(self):
        self._evt = threading.Event()
    def cancel(self):
        self._evt.set()          # 设置标志位
    def is_cancelled(self):
        return self._evt.is_set()  # 非阻塞查询
```

- `InferenceWorker.cancel()` → `cancel_token.cancel()` + `sink.close()`
- `ThreadedPipeline` 主循环有 4 个检查点调用 `is_cancelled()`
- 停止延迟 < 2 秒（取决于当前批次推理耗时）
- 停止后调用 `worker.terminate()` + `worker.wait(3000)` 兜底

### Q12: 配置编辑器怎么从 Pydantic 模型自动生成表单？

**三步流程**:

1. **获取分组和元数据**:
```python
groups = config.get_field_groups()  # {"核心参数": ["task", "model", "data"], ...}
meta   = config.get_field_metadata("batch")  # {description, default, examples, tips, ...}
```

2. **根据字段类型创建控件**:
```python
annotation = field_info.annotation

if annotation is bool:          → QCheckBox
elif annotation is int:          → QSpinBox(ge=..., le=...)
elif annotation is float:        → QDoubleSpinBox
elif annotation is str:          → QLineEdit
elif get_origin(annotation) is list: → QLineEdit（逗号分隔）
elif _is_optional(annotation):   → QCheckBox("启用") + 内层控件
elif _is_union(annotation):      → QComboBox（Union[bool,str]）
```

3. **双向同步**:
```
Form Tab → YAML Tab: get_values() → 序列化为 YAML 文本
YAML Tab → Form Tab: yaml.safe_load() → Pydantic 验证 → load_config()
```

### Q13: 配置编辑器怎么处理不存在的 YAML 文件？

```python
def _load_file(self, filename):
    if not filepath.exists():    # 文件不存在 → 用默认值
        self._load_defaults()
        return

    try:
        raw = yaml.safe_load(...)     # 读 YAML
        self._config = self._config_class(**raw)  # Pydantic 验证
    except Exception:
        logger.warning("加载配置失败")   # YAML 有错 → 回退默认
        self._load_defaults()
```

因为 `BaseConfig` 有 `model_config = ConfigDict(extra="forbid")`，YAML 里多了不认识的字段会抛 `ValidationError`，表单自动回退到默认值。

## 四、工程实践类

### Q14: 开发过程中遇到过什么 Bug？怎么解决的？

| Bug | 原因 | 修复方法 |
|-----|------|---------|
| `setTextColor` AttributeError | PySide6 的 `QPlainTextEdit` 没有这个方法 | 改用 `QTextCharFormat` + `setCurrentCharFormat` + `appendPlainText` |
| QObject/ABC 元类冲突 | `QtSignalSink` 同时继承 `QObject` 和 `OutputSink(ABC)` | duck typing 实现协议，不声明继承 ABC |
| ConfigForm Optional 类型误判 | 用了 `type(None)` 和 `type(...)` 检测 Union，这在 Python 3.10+ 不可靠 | 改用 `types.UnionType` + `get_origin()` + `get_args()` |
| 约束(ge/le)读取失败 | 访问了 `field_info.metadata`，但 Pydantic v2 的约束存在 FieldInfo 属性上 | 改用 `getattr(field_info, 'ge')` 直接读属性 |
| QHBoxLayout.addWidget(toolbar) | toolbar 是 QHBoxLayout 不是 QWidget | 改为 `addLayout(toolbar)` |
| validation_page.py 缺少 QColor | import 时漏掉了 | 补充 `from PySide6.QtGui import QColor` |
| od-desktop 启动崩溃 | 日志查看器在显示日志时崩溃，导致整个 app 起不来 | 逐一排查 LogViewer 的信号连接，修复 setTextColor |

### Q15: 如果要加第 7 个 Tab，需要改哪些文件？

1. **新建页面**: `pages/new_page.py` → 继承 `QWidget`
2. **如需要**: `workers/new_worker.py` → 继承 `BaseWorker`
3. **main_window.py**:
   - `TAB_LABELS` 列表加 `("新Tab名", "new_key")`
   - `_setup_ui` 的 `self._pages` dict 里实例化
4. **如需要专用 widget**: `widgets/` 下加文件

**改动量**: 大约 3-4 个文件，无需修改其他 Tab。

## 五、拓展思考类

### Q16: 如果推理帧预览很卡怎么办？

| 问题 | 解决方案 |
|------|---------|
| 刷新频率太高 | QTimer 从 33ms 调到 66ms（15FPS） |
| 大分辨率图片转换慢 | 缩小显示分辨率再转换 QPixmap |
| 帧积压 | on_frame 里做跳帧，每 3 帧只存 1 帧 |

### Q17: 如果要做 Web 端，现有桌面端代码哪些能复用？

```
桌面端                          Web 端
───                            ───
Worker(QThread)     →          Celery Task / asyncio
QtSignalSink        →          WebSocketSink（实现 OutputSink 协议）
Qt Signal/Slot      →          WebSocket push / SSE
ConfigForm 反射逻辑   →          后端 API 返回表单 schema
FrameViewer         →          <img> / <canvas> 标签
```

**关键是引擎提供的三个接缝**:
- `output_sink: OutputSink` — 换一个实现就能改输出目的地
- `hooks: InferHooks` — `on_frame`/`on_progress` 回调直接对接 WebSocket
- `cancel_token: CancelToken` — 线程安全的取消信号

### Q18: 你的模块在整个项目中处于什么位置？

```
apps/platform/          ← 核心引擎（D0-D8 的成果）
    │
    ├── ... (数据流水线、质检、训练、推理、帧源、美化...)
    │
apps/desktop/           ← 我的模块（扩展项）
    │
    └── import od_platform → 复用引擎全部能力
        不反向依赖，不重复造轮子
```

桌面端是**薄层**——只做 UI 展示和用户交互，所有业务逻辑都在引擎里。这是 D0 设计指南约定的分层原则。

### Q19: 你在这个项目中学到了什么？

1. **阅读大于重写**: 先理解引擎提供的接口（`OutputSink`、`InferHooks`、`CancelToken`、`BaseConfig.get_field_metadata()`），再思考如何对接
2. **元类冲突是真实存在的**: `QObject` 和 `ABC` 不能同时继承，duck typing 是 Python 里更务实的做法
3. **跨线程数据传递要 copy**: ndarray 零拷贝看似高性能，但线程间共享会导致竞态
4. **Pydantic + Qt 可以自动生成表单**: 反射 `model_fields` 的 annotation 和 metadata，几十个字段一行手写代码都不用
5. **用户感知的"卡"不等于真的慢**: 30FPS 限帧 + 缩放显示，引擎跑 90FPS 用户也感觉流畅
