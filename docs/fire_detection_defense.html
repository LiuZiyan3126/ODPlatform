01 Project

项目简介

项目背景

火灾具有突发性强、扩散速度快、人工巡检成本高等特点，传统人工监控难以及时发现早期火情，需要自动化视觉检测手段辅助预警。

核心用途

系统用于识别图像、视频或摄像头画面中的火焰与涉火人员目标，可应用于园区安防、实验室值守、现场巡检和边缘端火情预警。

技术路线

以 YOLO 目标检测模型为核心，配套数据处理、数据质检、配置管理、模型训练、模型评估、模型推理、报告输出和 PySide6 桌面端。

04 Route

项目实现路线

项目整体按照“数据流水线 → 数据质检 → 训练配置与模型训练 → 模型评估与对比分析 → 推理应用与客户端集成”的顺序实现，形成从原始数据到可展示产品的完整闭环。

数据流水线

项目首先通过 `odp-transform` 处理 fire 原始数据集：读取 `data/raw/fire`，将 Pascal VOC 等原始标注统一转换为 YOLO 标签格式。流水线支持 `preserve` 模式保留原始 train / val / test 划分，也支持重新划分、分层划分和稳定哈希划分。最终输出标准目录 `data/processed/fire` 与训练入口 `apps/platform/configs/datasets/fire.yaml`，并在 YAML 中写入类别表、划分数量、划分策略和 SHA-256 数据指纹，保证后续训练能明确知道“用的是哪一份数据”。

数据质检

数据集生成后，通过 `odp-validate` 对 `fire.yaml` 执行训练前质检。系统会检查 YAML 字段一致性、图像与标签是否成对、标签行格式、标注框几何合法性、图片完整性、孤儿标签、空标签、split 重复以及数据指纹一致性。质检结果不会修改数据，只输出报告包：`report.html` 用于展示，`issues.csv` 用于逐条整改，`report.docx` 用于归档交付，`report.json` 用于程序化读取。

训练配置与模型训练

数据通过质检后，训练模块读取运行时配置和数据集 YAML，基于 `yolo11n.pt` 启动火情检测模型训练。训练过程记录训练人、开始/结束时间、运行环境、模型结构、输入尺寸、batch、epoch、优化器、学习率等关键参数，并保存最佳权重、最后权重、训练日志和审计快照。训练结束后自动生成训练报告，说明“谁在什么数据上训练了什么模型，训练结果如何”。

模型评估与对比分析

训练完成后，评估模块使用 test 分片对模型进行独立评估，输出 Precision、Recall、mAP@50、mAP@50-95、Fitness 和逐类 mAP 等指标，同时保存 PR 曲线、F1 曲线、混淆矩阵、归一化混淆矩阵和预测样例图。对于多个候选模型，`odp-compare` 会在同一数据集、同一 test 分片上横向比较指标，帮助选择更适合展示和部署的模型，例如当前展示重点是 `train-4-20260707-233005-yolo11n-best.pt`。

推理应用与客户端集成

最终将训练好的模型接入推理系统，支持图片、图片文件夹、视频文件和摄像头等输入源。推理模块负责加载模型、读取帧源、执行 YOLO 检测、渲染检测框、统计 FPS / 帧数 / 检测数 / 耗时，并生成推理审计记录。桌面客户端基于 PySide6 实现单窗口多页应用，将项目初始化、数据流水线、数据质检、配置编辑、模型训练和模型推理整合到可操作界面中，使系统从命令行工具扩展为可演示、可交互的火情检测平台。

推理与终端：帧源和桌面端

客户端使用 PySide6 实现单窗口 QTabWidget，把平台核心流程做成可交互页面：项目初始化/重置、数据流水线、数据质检、配置编辑、模型训练、模型推理。长任务通过 QThread 与信号槽运行，日志和进度实时回传到界面。

  • 配置编辑器支持表单模式与 YAML 模式双向同步。
  • 训练页面解析日志展示 epoch、loss 和进度。
  • 推理页面支持摄像头、视频、图片、文件夹，并展示 FPS、帧数、检测数和耗时。
  • 帧源捕获模块采用注册表与自动注册机制，新增输入源时无需修改调度主流程。
python -m od_desktop.app

07 Summary

项目总结

本项目完成了从算法实验到工程平台的跃迁，但在真实生产环境、模型泛化能力、持续数据闭环方面仍有提升空间。

项目优点

  • 链路完整：覆盖数据处理、质检、配置、训练、评估、推理、报告和 GUI。
  • 可追溯性强：数据指纹、审计快照、训练报告、评估报告能复盘每次实验。
  • 工程扩展性好：注册表机制用于划分策略、质检项、帧源，后续加模块成本低。
  • 展示交付友好：HTML、Word、CSV、Markdown 多种报告格式适合答辩与归档。
  • 客户端完整度高：桌面端覆盖项目、数据、质检、配置、训练、推理等核心流程。

项目不足

  • 模型仍偏轻量，复杂烟雾、遮挡、小火源、夜间低质画面下泛化能力有待扩充数据验证。
  • 当前训练主要基于 CPU 环境记录，完整 GPU 训练与长期稳定性测试还可以加强。
  • 质检已能发现数据问题，但自动修复、主动再采样和数据版本管理还未完全自动化。
  • 桌面端已完成主体页面，仍需要更多空状态、异常提示、打包发布与用户体验打磨。
  • 推理预警尚停留在本地检测，后续可接入消息通知、监控平台和边缘设备联动。

后续展望

下一步可围绕“更强模型、更真实数据、更自动闭环”推进：增加烟雾与早期火苗类别，扩充多场景数据； 引入主动学习筛选低置信样本；完善桌面端打包发布、异常提示和报告输出，让 GUI 成为一体化操作台。
